# 칸몬해협 건물 API 조사 및 생성

이 보고서는 기존 보고서를 참조하지 않고 현재 원본 파일, 새 API 응답, 공식 문서와 실제 렌더링 결과에서 작성했다. 작업 대상은 칸몬해협이다. 큐슈 설정과 건물 자산 연결은 변경하지 않았다.

## 직접 확인한 문제

- 기존 원본 OSM 건물 way는 36,769개, 기존 생성 자산의 건물 레코드는 36,094개였다. 공간 분포가 일부 격자에 집중되어 있었다.
- 새 Overpass 응답의 building 태그 way 수는 37,535개였다. 원본 갱신만으로 채울 수 있는 양은 제한적이다. 새 수집 응답에는 외곽선 구성용 way와 복합 건물 relation도 포함된다.
- 기존 수집기는 파일 크기가 10 MB 이상이면 전체 영역 자료로 간주해 재수집을 건너뛴다. 실패한 격자도 계속 진행하며 최종 파일 크기로는 완료 여부를 판단할 수 없다.
- 기존 메시 빌더는 경사지 건물의 중심 표고로 지붕을 정해 높은 모서리에서 건물이 묻힐 수 있었다. 일부 작은 높이를 건물 폭에 따라 과도하게 늘리고, 중정을 일반 지붕으로 채우는 문제도 있었다.

## API 호출량과 공개 제한

| 자료 | 공식 공개 제한·운영 조건 | 이번 작업에서 확인한 호출 |
|---|---|---|
| Overpass / OSM | 주 인스턴스 권고는 약 10,000회/일, 1 GB/일 이내이며 보장된 할당량이 아니다. 슬롯은 부하와 실행시간에 따라 변한다. | 건물 개수·전체 외곽선 조회 성공 2회, GET 조회 HTTP 406 실패 1회, 상태 조회 1회. 상태 응답은 제한 2슬롯, 당시 가용 2슬롯이었다. |
| GSI PMTiles | 고정된 호출 횟수 한도는 확인한 공식 문서에 명시되지 않는다. 정상 운영에 영향을 주는 접근은 차단될 수 있다. | 본 수집 HTTP Range 39회, 40,894,464 bytes. 사전 표본·헤더 검증까지 포함하면 43회. 범위 안의 Z16 타일 3,136개를 캐시된 바이트로 해석했다. |
| OpenTopography global DEM | 무료 API 키는 일반 사용자 50회/24시간, 학술 사용자 200회/24시간. 계정 유형은 확인하지 않았다. | DEM 재수집 0회. 기존 GeoTIFF의 좌표 태그와 해상도를 직접 확인했다. |

출처: [Overpass 운영 문서](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html), [GSI 서비스 이용 규약](https://maps.gsi.go.jp/help/termsofuse.html), [OpenTopography 개발자 안내](https://opentopography.org/developers). 호출 수는 이번 작업의 데이터 조회 기준이며 문서 검색·패키지 다운로드와 다른 사용자의 호출은 포함하지 않는다. GSI 수집기는 순차 요청, 0.5초 간격, 캐시와 실행당 최대 300회 호출 예산을 사용한다.

## 정밀도와 선택한 자료

- GSI 최적화 벡터의 건물 레이어는 BldA이며 Z16을 사용했다. 공식 설명에 따르면 Z14·15는 작은 건물을 생략하고 Z16은 면적 기준 생략을 하지 않는다. PMTiles의 공식 갱신 기준은 2026년 7월 1일이다. [GSI 데이터 사양](https://github.com/gsi-cyberjapan/optimal_bvmap), [건물 상세도 설명](https://maps.gsi.go.jp/pn/meeting_partners/data/20221206/03_%E6%9C%80%E9%81%A9%E5%8C%96%E3%83%99%E3%82%AF%E3%83%88%E3%83%AB%E3%82%BF%E3%82%A4%E3%83%AB%E3%81%AE%E7%89%B9%E5%BE%B4.pdf).
- 실제 표본 타일의 extent는 4096이었다. 북위 33.9도에서 좌표 양자화 간격은 약 0.124m이다. 이는 인코딩 간격이고 측량 위치 오차가 0.124m라는 뜻이 아니다. GSI도 이 시험 공개 자료를 기본측량 성과로 보장하지 않는다. 표본 건물 속성은 vt_code, vt_lvorder이며 높이는 없었다.
- OSM 높이 값 19개를 사용하고, 층수 484개는 층당 3.2m로 환산했다. 나머지 321,081개, 약 99.84%는 건물 용도 또는 기본값으로 높이를 추정했다. 높이 태그의 존재도 실측 보증을 뜻하지 않는다. [OSM height 정의](https://wiki.openstreetmap.org/wiki/Key:height).
- 기존 COP30 GeoTIFF는 1080×900, 위경도 간격 1초, EPSG:4326이며 원점은 동경 약 130.8도·북위 약 34.05도였다. 4096 높이맵은 이 자료의 리샘플링 결과이며 원본보다 실제 지형 정밀도가 높아진 것은 아니다. COP30은 약 30m의 지표면 모델이므로 개별 건물 기초와 수목 제거 지반을 정밀 실측한 자료가 아니다. [Copernicus DEM 설명](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM).

## 생성 및 적용 결과

- 새 GSI 원본 371,956개 타일 폴리곤을 범위로 자르고 경계 중복·분할을 정리했다. OSM과 겹치는 GSI 외곽선은 중복 생성하지 않았다.
- 최종 건물 외곽선 레코드는 321,584개이다. 이는 처리된 폴리곤 수이며 건축물대장상의 동 수를 보증하는 숫자가 아니다. 복합 건물 50개 폴리곤을 복원하고 중복 외곽선 67개를 대체했다. 중정이 있는 건물 284개를 보존했다.
- 도로 1,157개와 방파제 4개는 기존 자료와 내용이 동일함을 확인했다. 공항 대체 부지의 건물은 기존 정책에 따라 런타임에서 제외한다.
- 칸몬 맵만 새 `buildings_20261003/buildings_and_roads.json`에 연결했다. 공간 캐시 5,371배치로 주변 자료를 읽고 이동 시 이탈 건물을 해제한다. 원본과 큐슈가 사용하던 자산은 보존했다.
- 경사지에서는 외곽 모서리의 최대 지반을 기준으로 지붕을 생성하며, 출처가 있는 높이 값은 폭에 따른 과장 규칙에서 제외했다. 중정은 제약 삼각분할과 내벽을 사용한다.
- M키 지도에 OSM/GSI 출처와 높이 추정 안내를 표시한다. 기존 도로·등고선 지도 이미지는 이번에 다시 생성하지 않았다.

## 새 검증 결과

| 검증 지역 | 반경 약 3km에 읽힌 건물 원본 수 | 관측 FPS |
|---|---:|---:|
| 고쿠라 | 39,323 | 60 |
| 모지코 | 15,054 | 60 |
| 시모노세키 | 28,667 | 60 |
| 시모노세키 북부 | 20,301 | 60 |

실제 Vulkan 렌더링 화면을 저장하고 지역 이동에 따른 캐시 로딩을 확인했다. 표의 숫자는 읽힌 원본 수이며 화면에 전부 표시되는 수가 아니다. FPS는 지정 카메라와 기존 사용자 설정에서의 짧은 관측값이며 모든 위치의 성능 보장은 아니다.

- 높이 3m 건물을 경사지 최대 지반 10m에 놓았을 때 지붕 13m를 검증했다.
- 10×10m 건물의 4×4m 중정을 제외한 지붕 면적 84㎡를 검증했다.
- 현재 자산의 ID 321,584개가 고유하고 좌표가 구현 범위 안에 있음을 검증했다. 공간 배치 5,371개의 해시와 원본 해시를 확인했다.
- 근거 파일: `261003_kanmon_building_generation_metrics.json`, `261003_gsi_building_http_metrics.json`, `261003_kanmon_building_asset_validation.json`, `261003_kanmon_building_render_validation.json`, `261003_kanmon_building_mesh_validation.json`.

## 보관 및 재현

새 원본은 해시를 확인한 ZIP `data/archives/kanmon_building_sources_20261003.zip`으로 보관했다. 약 166.0 MB를 34.0 MB로 줄였고 원본 SHA-256은 보존했다. `BuildingSourceStore`가 압축 원본을 직접 읽는다. 이번 작업의 미사용 중간 공간 캐시 약 224.6 MB도 정리했다.

프로젝트 가상환경 `.venv_campus/Scripts/python.exe`를 명시해 `pipeline/processors/build_kanmon_buildings.py`, 이어서 `pipeline/indexer/index_kanmon_buildings.py`를 실행하면 저장된 원본에서 재생성·검증·색인할 수 있다. GSI 신규 수집은 `pipeline/collectors/gsi_building_collector.py`이며 전체 전국 파일 약 16.9 GB를 내려받지 않고 필요한 범위만 읽는다. 의존성은 `pipeline/requirements_kanmon_buildings.txt`에 기록했다. 두 모듈 인덱스와 자산 매니페스트의 해시·범위·고도·해상도·배치 수를 갱신했다.
