# 울산 80km 맵 우선 건물 구현 계획

## 1. 목적과 현재 기준

울산 60km 권역의 건물 전수 구축 이후, 먼저 울산 80km 맵의 미구축 외곽을 채우고 그 다음 동남권 140km 맵의 울산 외 도시권을 단계적으로 반영한다. 두 맵 모두 전체를 동일 밀도의 건물 메시로 채우지 않고, 비행·조망에 필요한 시가지와 산업·항만 거점을 우선한다.

- 1차 대상 맵: `ulsan_metro_80km` (35.1841~35.9049°N, 128.8125667~129.6984333°E)
- 2차 대상 맵: `southeast_mega_140km` (설정 BBox 기준 부산·김해·창원·밀양·경주·포항 등)
- 80km 맵 자산: 지형·행정구역·수계와 독립 `buildings_and_roads.json`이 존재하며, 외곽 캐시와 기존 60km 상세 건물을 병합 완료
- 기존 울산 상세자료: `ulsan_metro_60km` 건물은 80km 맵 범위와 겹치므로 그대로 재사용하고, 겹치는 범위를 다시 요청하지 않음
- 140km 맵 기존 자산: `southeast_mega_140km/buildings_and_roads.json`; 실제 건물 커버리지와 80km/60km 공용 범위는 수집 전 점검
- 수집 기준: VWorld `LT_C_SPBD`, 공식 상세 문서 기준 페이지당 최대 1,000건, 셀 요청 면적은 2km² 이하로 설계. 2026-09-30 실요청 검증 근거는 `260930_VWorldApiDiagnosisReport.md` 참조
- 운영 근거 갱신: 사용자가 제공한 VWorld 키 관리 화면에서 일일 접속·사용량 제한이 무제한으로 표시된 것을 확인했다. 이번 80km 작업은 2026-09-30 매니페스트 기준 1,637회 요청으로 완료했으며, 이 실측 결과는 계정의 모든 API 유형에 대한 보편적 무제한을 의미하지 않는다.
- 셀 완료 판정: 모든 페이지의 성공 응답, 셀 캐시의 유효 JSON, 셀 경계 내 피처 검증을 마친 경우에만 완료로 기록

기존 울산 5단계 계획에는 Phase 5의 30셀 그리드와 Phase 4의 24셀 등 초기 표의 셀 수가 일치하지 않는 차이가 있었다. 80km 외곽은 실제 BBox를 2km² 이하로 재격자화한 1,520개 셀로 전수 수집을 완료했다(최대 면적 1.94km²). 기존 일차 표의 760셀은 이전 계획값이며 실제 실행 셀 수가 아니다.

## 2. API 호출 예산 원칙

- 사용자가 제공한 VWorld 키 관리 화면은 일일 접속 건수와 사용량을 무제한으로 표시했다. 이번 80km 작업에서 1,637회 요청이 성공적으로 기록됐다. 이는 해당 화면과 이번 작업의 실측이며 다른 계정·키·API 유형 전체의 무제한을 뜻한다고 확대 해석하지 않는다.
- 모든 HTTP 요청과 재시도를 매니페스트에 기록한다. 제한 오류, HTTP 429/5xx 또는 연속 시간 초과가 발생하면 진행을 멈추고 응답과 계정 화면을 점검한다.
- 셀 면적은 위경도 단순 제곱도가 아닌 지리적 면적 계산으로 검증한다. 해안·산악·수면만 포함하는 셀은 사전 마스크해 공호출을 줄인다.
- 셀 페이지 수는 첫 페이지의 전체 건수(total)로 예상한다. 1,000건 단위의 깊은 페이지네이션이 필요한 고밀도 셀은 더 작은 하위 셀로 재분할한다.
- 오류 응답, 비정상 JSON, 시간 초과, HTTP 429/5xx가 발생하면 해당 페이지 이후 진행을 멈춘다. 응답을 정상 종료로 간주하거나 빈 셀로 기록하지 않는다.
- 동일 키·동일 IP의 다른 수집 작업 사용량까지 고려한다. 프로젝트 매니페스트의 사용량만으로 계정 전체 잔여량을 단정하지 않는다.

## 3. 우선순위와 1일 단위 수집 일정

권역 BBox와 셀 수는 행정구역 경계 및 도시화 마스크를 이용해 실행 직전에 확정한다. 표의 대상과 순서는 지리적 우선순위이며, 호출 수는 실제 응답과 계정 화면을 바탕으로 산정한다.

| 순서 | 대상 맵·권역 | 우선 포함 지점 | 일일 호출 목표 | 완료 기준 |
|---|---|---|---:|---|

| 2 | 80km 서부·남부 외곽 | 언양·상북·삼남 외곽 및 양산 북부·웅상 등 BBox 안 도시화 지역 | 완료 | 계획 셀·매니페스트·캐시 대조와 병합 완료 |

## 4. 구현 및 데이터 관리

1. `ulsan_metro_80km` 경계와 소스 맵 경계를 공간 대조해 60km 맵의 건물 커버리지를 먼저 마스크한다. 80km BBox에서 내부 상세맵 자산으로 이미 덮인 곳을 재수집하지 않는다.
2. 80km 범위 중 60km 바깥의 시가지 셀을 먼저 생성한다. 이어서 외곽 자료를 60km 자산과 병합해 80km 런타임 건물 자산을 만든다.
3. 80km 점검과 병합이 끝난 뒤, `southeast_mega_140km` 범위에서 80km 및 60km 자산과 겹치는 구간을 마스킹하고 부산·김해·창원·밀양·경주·포항을 수집한다.
4. 각 맵에 전용 원본 셀 캐시와 `manifest_progress.json`을 둔다. 매니페스트에는 날짜별 요청 수, 누적 완료 셀, 페이지 진행 위치, 오류, 피처 수, 해시를 기록한다.
5. 권역별 BBox를 도시화/행정구역 마스크에 맞춰 자르고, VWorld 요청 기준에 맞춰 셀 면적 2km² 이하와 셀 간 틈·중복이 없는지 확인한다.
6. 중복 제거 키는 `bd_mgt_sn`을 우선 사용한다. 식별자가 없는 피처는 원천 `id`와 정규화한 형상을 조합해 별도 감사 목록에 남기며 조용히 버리지 않는다.
7. 일일 수집은 완료 셀을 건너뛰고 미완료 셀의 마지막 성공 페이지 다음부터 재개한다. 페이지 응답을 디스크에 먼저 안전 저장한 후 진행 상태를 갱신한다.
8. 원본 셀 캐시는 불변 보관하고, 정규화·선택·렌더링 파생본을 따로 생성한다. 각 맵의 자산 병합 시 60km, 80km, 140km 간 중복을 제거한다.
9. 전수 수준의 건물은 도심 및 비행 고도에서 식별 가치가 큰 산업·항만 중심으로 제한한다. 그 외 농촌·산악 지역은 대표 랜드마크 또는 저밀도 요약 표현을 사용하고, 전수 커버리지와 렌더링 자산 범위를 구분해 기록한다.

## 5. 완료 검증 체크리스트

- 계획 셀 목록, 완료 매니페스트, 실제 캐시 파일이 정확히 일치한다.
- 각 셀의 성공 페이지 수가 API 전체 건수 기준에 도달했으며 오류 페이지가 미해결 상태로 남아 있지 않다.
- `bd_mgt_sn` 중복·누락 수, 셀 경계 밖 피처, 빈 셀 응답의 근거를 권역별 보고서에 기록한다.
- 권역별 원본 피처 수, 고유 건물 수, 병합 전후 수, 런타임 자산 내 건물 수를 비교한다.
- 자산 해시와 BBox를 매니페스트에 기록하고, 최종 맵의 커버리지 경계와 행정구역을 시각적으로 검토한다.
- 완료 보고서에는 실제 호출 수, 계정 화면에서 확인한 일일 한도 상태, 미수집 구역·셀, 렌더링 확인 결과를 구분해 기록한다.
- 80km 맵은 60km 자료 포함부와 신규 외곽 자료를 구분해 커버리지를 보고하고, 140km 맵과 자료를 공유할 경우 출처와 중복 제거 결과를 함께 기록한다.

## 6. 울산 5일차 완료 상태에 대한 선행 확인

2026-09-30 로컬 자료 기준 `ulsan_metro_60km/buildings_cache`의 Phase 1~5 완료 목록과 캐시 파일은 각각 16/16, 12/12, 18/18, 24/24, 30/30으로 맞고, 총 100개 파일과 완료 셀이 일치한다. Phase 5의 6×5 격자에서 미완료 셀은 없다. 이는 모든 계획 셀에 캐시가 존재한다는 확인이며, VWorld 원본의 완전성이나 현재 Godot 렌더 프레임에서 모든 건물이 보인다는 독립 검증과는 구분한다.

기존 2026-09-29 Phase 5 보고서는 당시 15/30 셀, 런타임 건물 113,562동, 누적 호출 329회를 기록한다. 2026-09-30 기준 60km 원본은 계획 셀 100개와 캐시 파일이 일치하고 고유 식별자는 129,215개다. 이후 80km 전수 수집에서는 BBox에서 60km 내부를 제외한 외곽을 1,520셀(셀 최대 1.94km²)로 재격자화해 1,637회 요청으로 완료했다. 80km 완료 보고서 `260930_Ulsan80kmBuildingCompletionReport.md`가 외곽 및 병합 실적을 기록한다. 다음 구현 범위는 140km 맵의 울산 외 권역이며, VWorld 계정 화면의 사용량 표기와 API별 응답 동작을 확인하면서 계획한다.
