# 전체 구역 사전 준비 및 자원 유지

- 건물 스트림의 거리 기반 삭제 및 8만 동 상한을 제거했다. 생성된 건물·도로는 지도 종료까지 보유한다.
- 초기 가시권 준비 후, 이동 여부와 관계없이 전체 인덱스의 남은 구역을 가까운 순서로 준비한다. 이동하면 현재 위치 기준으로 우선순위를 갱신한다.
- 전 구역 준비 완료 여부와 읽기·검증·JSON 처리 시간, 건물 메시 생성·제출 시간을 기록한다. 후자는 GPU 전송 단독 측정값이 아니다.
- 프레임별 준비 예산은 8ms로 조정했다. 단일 메시 생성은 중간에 선점하지 못한다.
- 건물 표시 여부 갱신 간격을 250ms에서 50ms로 줄였다.
- 지형은 이미 만들어진 LOD 메시 및 충돌체를 보관하여 재방문 시 재사용한다. 아직 생성되지 않은 고해상도 LOD는 접근 시 생성한다.
- 지연 원인으로 코드에서 확인된 사항: JSON 파싱, 지형 표고 샘플링, 폴리곤 삼각화와 정점 생성, 도로 세분화, 프레임 대기, 기존 건물 삭제 및 재생성. 실제 단계별 소요 비중은 측정하지 않았다.
- 자원 참조를 유지하지만 물리 VRAM 상주는 운영체제와 GPU 드라이버가 관리한다. 전체 자원 유지로 메모리 사용량은 증가한다.
- 실행 테스트 및 고속 이동 성능 측정은 수행하지 않았다. 전체 준비 전 미방문 구역의 즉시 표시를 보장하지 않는다.
