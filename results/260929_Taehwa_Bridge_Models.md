# 태화강 교량 모델 구현

## 구현 범위

- 울산대교: 주경간 1,150m, 주탑 2개, 주케이블, 행어, 접속교와 교각을 생성한다. 양방향 OSM 선형을 평균한 하나의 상판으로 기존 도로 두 개를 대체한다.
- 십리대밭교: 120m 주경간, 비대칭 아치와 행어, 보행 상판 및 난간을 생성한다. 원본 경로에 포함된 접근 구간도 유지한다.
- 삼호교: 일반 거더교 구성. 구삼호교는 짧은 반복 경간과 콘크리트 난간으로 구분한다. 주변 신삼호교 양방향도 별도 배치한다.
- 일반 교량: 기존 RoadMeshBuilder의 공통 교량 생성기를 유지한다. 별도 재사용 가능한 120m 일반 교량 씬도 제공한다.
- 징검다리: 분리된 돌과 충돌 형상을 가진 60m 독립 모델을 생성했다. 정확한 대상 위치를 사용자에게 질문했으며 월드 배치는 보류했다.
- 교량 부재를 재질별 메시로 합쳐 노드 증가를 제한한다. 상판과 징검돌에는 충돌 형상을 생성한다.
- 60km와 80km 지도에서 각 지도 경계에 맞춰 위경도를 변환한다. 기존 도로의 OSM ID가 일치할 때만 대체한다.

## 독립 에셋

`godot_project/assets/generated/bridges/` 폴더의 씬은 첫 경로점을 원점으로 만든 미리보기/재사용 에셋이다. 실제 지도에서는 동일 생성기에 현지 지형 높이를 전달한다.

| 파일 | 대상 |
|---|---|
| bridge_00.scn | 울산대교 |
| bridge_01.scn | 십리대밭교 |
| bridge_02.scn | 삼호교 |
| bridge_03.scn | 구삼호교 |
| bridge_04.scn | 신삼호교 남행 |

## 자료와 정확도

- [OpenStreetMap](https://www.openstreetmap.org/copyright): 교량 경로와 객체 ID. 원본은 `data/raw/ulsan_metro_80km/bridges/bridges_osm.json`에 저장했다. ODbL 1.0 및 기여자 표시를 카탈로그에 기록했다.
- [울산광역시 태화강 국가정원](https://ulsan.go.kr/s/garden/bbs/view.ulsan?bbsId=BBS_0000000000000167&dataId=27111&mId=001002003000000000): 십리대밭교 길이 120m, 폭 5~8m를 참고했다. 모델 폭은 6m로 근사했다.
- [현대건설 교량 자료](https://www.hdec.kr/FileContents/OldFiles/HDEC_NEWSPAPER/005925539.pdf): 울산대교 주경간 1,150m를 참고했다.
- 구삼호교 OSM의 `width=210`은 교량 폭으로 사용하기에 부적합하므로 5m로 재정의했다.
- 측량이나 실시설계 수준의 복원은 아니다. 울산대교 주탑은 선형 중앙에서 주경간 길이로 배치했으며, 상판 해발 65m·주탑 상단 203m는 근사 설계값이다. 주탑의 실제 기초 좌표 확인과 높이 조정이 필요하다.
- 십리대밭교의 아치 곡선, 구삼호교의 부재 단면과 경간, 일반 교량 폭은 형태 구분을 위한 근사값이다.

## 생성 결과와 남은 작업

- Godot 씬 내보내기로 8개 에셋을 생성했다. 최초 생성 중 자료형 선언 오류를 수정했다.
- 카탈로그, 원본 해시, 독립 씬 해시와 양쪽 모듈 인덱스를 갱신한다.
- 실제 게임 화면에서의 외관, 접근 도로 높이 연결, 충돌 주행은 아직 확인하지 않았다.
- 징검다리는 위치 확인 후 해당 수면 고도와 횡단 길이에 맞춰 배치해야 한다.
- 이번 교량 수집에는 Overpass 요청 2회를 사용했다. VWorld 건물 API는 호출하지 않았다.

## 재생성 순서

- 지정 Python으로 `pipeline/processors/build_taehwa_bridge_catalog.py` 실행.
- Godot 프로젝트에서 `res://scripts/terrain/bridge_asset_export.gd`를 스크립트 진입점으로 실행.
- 같은 Python 카탈로그 생성기를 다시 실행하여 생성 씬의 해시를 매니페스트에 반영.
