# 북큐슈 구현 범위 좌표 및 해수 표시 수정

앞선 작업에서 큐슈 전체 범위를 100km 월드에 적용하면서 실제로 재사용한 칸몬 DEM·건물 자료와 불일치가 발생했다. 같은 높이맵의 상한을 750m 대신 1,980m로 해석해 고도가 증가했고, 바다 영역이 해수면 위로 올라왔다. 이전 공항·지도 보고서의 큐슈 전체 범위 및 18개 공항 배치 설명은 이 보고서로 대체한다.

- 맵 이름과 ID는 큐슈/kyushu_wide로 유지한다. 구현 범위는 원본과 같은 북위 33.8–34.05도, 동경 130.8–131.1도, 월드 28km이다. 고도 디코딩은 -50–750m로 통일했다.
- 지형, 수계, 건물, 도로, 행정경계, 랜드마크, 공항, M키 지도에 같은 지리 범위를 사용한다. 원본과 목표 범위가 같으면 벡터 재투영을 생략해 건물 좌표와 기존 도로 고도를 보존한다.
- 구현 범위 안의 기타큐슈공항과 오즈키 비행장 2곳만 배치한다. 범위 밖 16곳은 런타임에서 배치하거나 지형을 평탄화하지 않는다. 기존 모델 라이브러리는 보존한다.
- 원본 DEM의 해수면 저지대 중 래스터 경계와 연결된 영역을 해수 마스크로 분리했다. 2048×2048 픽셀 중 2,265,067개를 해수로 분류했다. 해수 지형은 해수면 아래로 제한하고 해수면 메시에는 이 마스크를 사용한다. 기존 내륙 수계 마스크와 구분한다.
- M키 지도는 동일 DEM·해수 마스크·수계·도로·공항에서 다시 생성했다. 큐슈 전체 Natural Earth 지도를 더 이상 사용하지 않는다. 범례에 북큐슈 구현 범위 28km를 표시한다.
- 원본 래스터와 건물·도로 JSON은 수정하지 않았다. 새 해수 마스크를 두 맵이 공유한다. 큐슈 월드는 64개에서 16개 지형 청크로 줄어들었다.

## 검증

실제 GPU로 칸몬과 큐슈를 로딩해 공항 수와 지반 정렬, 벡터 투영, 건물 원본 좌표 보존, 원본 DEM 범위·고도 설정 및 공항 부지를 제외한 해수 영역 표본의 음수 지형고를 검사한다. 최종 결과는 `261003_japan_airport_validation.json`에 기록했다. M키 HUD의 표시·확대·이동 좌표·행정경계·월드 범위 8개 검사는 통과했으며 `261003_kyushu_map_hud_validation.json`에 기록했다. 도로·교량 회귀 결과는 `road_render_validation.json`에 기록했다.

## 유지보수와 한계

해수 마스크는 Godot에서 `pipeline/processors/build_north_kyushu_sea.gd`, 사용자 지도는 `pipeline/processors/build_kyushu_tactical_map.gd`를 프로젝트 경로와 스크립트 절대 경로를 지정해 실행하면 재생성된다. 새 모듈과 셰이더는 두 모듈 인덱스에 등록하고 자산 매니페스트의 해시·범위·고도·해상도를 갱신했다.

해수 분리는 원본 DEM의 해수면 연결성을 이용하므로 원본 해안선 정밀도에 의존한다. 원본은 정사각형 월드에 위경도 범위를 대응시키는 기존 규약을 사용하며, 공항 모델도 같은 규약을 따른다. 오즈키 활주로 북단 일부는 구현 범위를 넘는다. 큐슈 전역 지형·공항을 구현했다는 의미가 아니다.
