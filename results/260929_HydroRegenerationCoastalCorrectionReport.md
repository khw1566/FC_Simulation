# 수계 재생성과 해안 지형 후보정

## 원인과 수집

- 기존 생성기는 해안선을 선으로만 그려 바다 면적을 수계로 채우지 않았습니다. 실제 바다에서 수계 0, 지형 약 1.29m로 표시된 현상을 설명하는 원인입니다.
- 기존 프로젝트에서 사용하는 Overpass API로 80km 범위와 주변 여유 영역을 새로 수집했습니다. 첫 엔드포인트 오류 후 두 번째 엔드포인트에서 완전한 응답을 받았습니다.
- API 객체 3,815개를 해안선 83개, 강·수로 1,990개, 호수·저수지 등 수역 1,742개로 분류했습니다. 이 수는 고유한 강이나 호수의 개수가 아니라 OSM 객체 수입니다.
- 원본 응답: `data/raw/ulsan_metro_80km/hydro_refresh/water_raw.json`. 출처 OpenStreetMap contributors, ODbL.

## 생성 파일

각 맵의 `hydro/` 폴더에 다음 파일을 만들었습니다.

- `coastline.geojson`, `river.geojson`, `lake.geojson`: 별도 원본 정밀도 벡터. 관계의 분리된 외곽을 연결하고 내측 섬을 내곽으로 기록했습니다. 벡터에는 맵 밖 여유 구역도 포함됩니다.
- `sea_mask.png`: 해안선을 장벽으로 삼고 동쪽 동해에서 연결된 바다 면적을 채운 마스크.
- `coastline_mask.png`: 해안 경계 마스크.
- `river_mask.png`, `lake_mask.png`: 내륙 수계별 마스크.
- `water_mask.png`: 기존 도로·지도 등과의 호환용 통합 마스크.
- `coastal_heightmap_16bit.png`: 후보정 높이맵.
- `processing_report.json`: 해상도, 변경 고도 및 처리 통계.

60km는 4,096², 80km는 5,632²이며 픽셀 간격은 각각 약 14.65m, 14.21m입니다. 벡터는 API 좌표를 유지하지만 미터 단위 실측 정확도를 보장하는 자료는 아닙니다. 폭이 없는 하천 중심선은 본류 25m, 소하천·수로 6m를 추정하므로 해당 폭은 실측값이 아닙니다.

## 해안 후보정

- 해안선이 지나는 래스터 셀의 목표 고도를 0m로 지정했습니다. 16비트 인코딩 반올림으로 약 1cm 오차가 생길 수 있습니다.
- 육지 방향 150m 구간은 0m에서 원본 고도로 부드럽게 연결합니다.
- 해상은 거리에 따라 완만하게 낮춰 최대 -20m의 시각화용 해저를 구성합니다. 실측 수심 자료가 아닙니다.
- 60km 최대 하향 변화 약 43.88m, 80km 약 55.21m입니다. 산지 해안도 150m 연결 구간에 포함되므로 원본 지형을 그대로 유지하는 처리는 아닙니다.
- 원본 지형을 보존하고 메타데이터의 `hydro_source_heightmap`에 기록했습니다. 반복 처리도 원본에서 시작합니다.
- 런타임에서 기존 통합 수계 절토를 중복 적용하지 않도록 했습니다. 공항 정지 작업은 유지합니다.

## 렌더링과 지도 연결

- 바다 평면은 통합 수계 대신 바다 전용 마스크를 사용합니다. 바다 수면은 해발 0m 평면이며 지형의 굴곡을 따라가지 않습니다.
- 지형 셰이더는 바다와 내륙 수계를 구분하고 호수에 별도 색조를 적용합니다.
- 내륙 강·호수의 수면 고도 평탄화는 이번 해안 후보정 범위에 포함하지 않았습니다. 특히 호수별 실제 수위는 별도 자료가 필요합니다.
- M 지도와 미니맵도 새 수계와 높이맵으로 다시 생성했습니다.
- 두 맵의 자산 매니페스트와 모듈 인덱스를 갱신했습니다.

## 실행 상태

- API 수집, 벡터·마스크 생성, 지형 후보정, 지도 재생성까지 완료했습니다.
- 게임을 다시 실행해 적용합니다. 이번 작업에서는 게임 실행 테스트나 수동 비행 확인을 수행하지 않았습니다.
- 재생성 순서: 지정 Python으로 `pipeline/collectors/hydro_refresh.py`, 이어서 `pipeline/processors/rebuild_hydro_terrain.py`를 직접 실행합니다.
