# VWorld 키 확인 및 울산 80km 건물 수집 재시도

> 2026-09-30 14:50 이후 정정: 등록값 `domain=없습니다` 전달로 같은 인증키의 건물 조회가 성공했다. 도심 75건 조회와 계획 2셀·고유 건물 2,767개 저장을 검증했다. 아래는 해결 전 이력이며, 최신 판단은 `260930_VWorldApiDiagnosisReport.md`를 따른다. domain 확인 전 추가 시험이 불가능하다는 이전 판단은 철회한다.

2026-09-30 실행 기록. 사용자 제공 인증키는 코드에 환경변수로만 전달했으며 `data/api_keys.json`에는 저장하지 않았다.

## 실행 결과
- 울산 80km 북부·동부 1일차 수집기를 실제 실행했다. 현재 수집 코드가 만든 후보는 254셀이고, 셀의 최대 면적은 5.557km²였다.
- 첫 셀에서 HTTP 200 응답을 받았지만 VWorld 응답 상태는 `ERROR`, 코드 `INCORRECT_KEY`였다. 오류 설명은 인증키가 올바르지 않다는 내용이다.
- 자동 재시도 2회와 오류 응답 확인 1회를 포함해 매니페스트 기록 호출 수는 5회다. 앞선 네트워크 차단 실행 2회는 API 응답을 받지 못했고, 이번에는 3회 모두 서버의 HTTP 200/API 오류 응답을 확인했다.
- 새 셀 완료 0/254, 새 건물 0, 80km 런타임 건물 자산 변경 없음. 일일 호출 제한 오류는 발생하지 않았다.
- 따라서 계정 화면에 표시된 일일 무제한 여부나 실제 호출 한도는 이번 결과로 판정할 수 없다. 먼저 해당 키가 VWorld 데이터 API용으로 유효한지와 승인 상태를 확인해야 한다.

## 기존 건물 데이터 상태
- 60km 계획의 5개 단계는 기존 매니페스트 기준 100셀 완료(16/16, 12/12, 18/18, 24/24, 30/30), 고유 건물관리번호 129,215개다.
- 80km 맵 메타데이터는 기존 60km `buildings_and_roads.json`을 참조한다. 해당 런타임 파일은 존재하며 크기는 117,217,336바이트다. 이는 기존 60km 범위의 공유 자산이고, 이번 80km 바깥 확장 수집 실적은 아니다.

## 계획과 코드의 불일치
- 이전 80km 1일차 보고서는 후보 218셀을 기록했지만 현재 실행 파일은 254셀을 생성한다. 수집 코드는 보고서의 수량과 일치하지 않으며, 육지·도시화 마스크를 적용해 공호출 영역을 줄이는 검증도 다시 해야 한다.
- 호출 목표 600회와 절대 상한 700회는 유지했다. 인증키가 거부된 시점에 수집을 멈췄으므로 호출 제한 시험은 완료되지 않았다.
- 인증키를 바로잡고 1일차 셀 목록을 대조한 뒤 매니페스트에서 재개해야 한다. 다른 저장 키로 대체하거나 상한을 높여 재시도하지 않았다.

## 화면 설정과 오류의 대조 (정정)
- 사용자가 제공한 VWorld 인증키 관리 화면에는 서비스 유형이 웹사이트로 선택되어 있고, 서비스 URL 입력란에는 `없습니다`라고 표시된다. 2D 데이터 API는 사용 API로 체크되어 있다. 화면의 일일 접속 건수·사용량 무제한 표시는 사용량/쿼터 정보이며 인증 출처 검증 성공을 뜻하지 않는다.
- 수집기 요청에는 `domain` 파라미터가 없었다. 이 때문에 등록된 웹사이트 URL/domain과 호출 출처가 맞지 않아 `INCORRECT_KEY`가 났을 가능성이 있다. 단, 화면 캡처만으로 실제 저장된 등록값을 확인할 수 없고 API 응답도 키 문자열 오류와 domain 오류를 구분하지 않으므로 이는 확정 원인이 아니라 우선 확인할 가설이다.
- 수집기는 `VWORLD_DOMAIN` 환경변수가 설정된 경우에만 요청의 `domain`으로 전달하도록 변경했다. 실제 등록된 서비스 URL의 도메인과 일치하는 값이 확인되기 전에는 추가 API 요청을 보내지 않는다. URL 값이 정말 `없습니다`라면 VWorld 포털에서 실제 서비스 유형과 등록 URL/domain을 확인·수정해야 한다. 브라우저용 웹사이트 키를 쓰는 경우 브라우저 호출 출처도 등록 도메인과 일치해야 한다.
- 따라서 키가 틀렸다고 단정했던 기존 실행결과 설명을 정정한다. 인증 원인은 아직 미확정이며, 앞선 시도는 인증 오류로 끝나 호출한도 시험이 아니다.
