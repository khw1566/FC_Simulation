# 선박 증편·정박·항적

- 울산 80km: 기존 운항 10척에서 운항 30척과 정박 20척, 총 50척으로 증편했다. 울산 본항·온산항 각 15척, 방어진항·진하항 각 10척이다.
- 기존 일본 지도 두 곳도 각각 운항 21척과 정박 14척으로 증편했다.
- 운항 편성은 기존 종류별 항로를 공유하며 출발 위상을 분산한다. 정박 편성은 mode=moored로 명시하고 고정 위치와 방향을 사용한다.
- 정박 위치는 해수 마스크의 선체 반대각선+15m 침식 영역에서 선택한다. 정박 선박끼리의 선체 간격과 동일 종류의 운항 경로 이격을 확인한다. 실제 부두 접안 좌표나 실제 항만 운항 규칙을 재현하지 않는다.
- 선미가 지나간 세계 좌표에 거품 항적을 생성한다. 폭은 선폭, 수명은 선체 길이, 거품 농도는 속도에 비례한다. 시간이 지나면 항적이 넓어지고 흐려진다.
- 정박 및 운항 중 대기 구간에서는 새 항적을 만들지 않고 기존 항적은 자연 소멸한다. 거리 밖에서는 항적을 제거하며 기존 선박 설정을 끄면 모든 선박과 항적을 함께 제거한다.
- 항적은 선박당 최대 192개 표본, 0.35초 갱신 간격과 최대 65초 수명으로 제한한다. 전용 모듈과 셰이더를 사용한다.
- 전체 맵 실행 없이 Godot 문법 검사 및 경량 항적 검사 통과: 울산 운항 30척·정박 20척, 정박 좌표 유지, 항적 생성·소멸, 선박 크기 비례 확인. 실제 렌더 화면과 장시간 운항은 미검증이다.
- 원본 선박 GLB와 모델 씬은 수정하지 않았다. traffic.json과 공통 매니페스트의 vessel_traffic 항목을 갱신했다. 양쪽 module_index.json에 VesselWake를 등록했다.
- `.venv_campus/Scripts/python.exe pipeline/indexer/build_asset_index.py`로 전체 에셋 색인 갱신: 23,168개 파일, pending 0개. 추가 셰이더를 포함한다. 프리뷰 실행파일은 재빌드하지 않았다.
