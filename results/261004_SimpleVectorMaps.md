# 계층 마스크 기반 단순 벡터 지도
새 AGENTS.md의 동시 작업 보호와 경량 개발 지침을 확인하고 등록된 6개 지도 전체의 지도 이미지를 단순한 색상 계층 SVG로 제작했다. 게임 실행마다 원본이나 지도를 재생성하지 않으며 수동 명령으로만 갱신한다.

## 구현 결과
- 해안선, 대로, 철로, 강, 호수, 항구, 항로, 산지, 건물 및 바다 배경을 분리했다.
- 각 계층에 흑백 SVG와 8-bit PNG 마스크를 제공하고 색상을 입혀 최종 SVG를 합성한다.
- 최종 SVG는 PNG를 내부에 삽입한 파일이 아니라 실제 벡터 경로와 면으로 구성한다.
- 산지는 기존 16-bit 높이맵을 미터 단위 고도로 복원하고 150·350·700·1100m 영역을 단계적으로 중첩했다.
- 건물은 10km 이하 소형맵만 표시한다. 광역맵은 건물 밀도로 주요 선형이 가려지지 않게 생략한다.
- 도로는 간선 분류를 우선 사용한다. 소형맵의 원본은 모든 도로가 residential로 저장되어 있어 폭 14m 이상 자료도 선택했다.
- 140km 지도에는 기존 소형맵과 80km 도로 자료를 지리 좌표로 재투영했다. 미수집 외곽을 추정 도로로 채우지 않았다.
- 항구·항로는 별도 GeoJSON 입력 어댑터와 색상·마스크를 준비했다. 현재 입력 파일이 없어 비어 있으며 기존 선박 운항 작업을 수정하지 않았다.

| 정보 | 색상 |
|---|---|
| 해안선 | 청록 |
| 대로 | 주황 |
| 철로 | 보라 |
| 강 | 하늘색 |
| 호수 | 파랑 |
| 항구 | 빨강 |
| 항로 | 초록 |
| 산지 | 갈색, 고도별 강도 차이 |
| 건물 | 회색 |

## 수동 갱신
프로젝트 루트에서 아래 명령으로 전체 지도를 갱신한다.

```powershell
./pipeline/update_map_images.ps1
```

특정 지도만 갱신하려면 `-Maps ulsan_uc_west,ulsan_metro_80km`을 지정한다. 설정은 `config/simple_vector_maps.json`에 있다. 원본이 그대로면 생성을 건너뛰며 색상만 변경하면 저장된 형상·마스크 데이터를 재사용한다. 이번 환경에서 변경 없는 6개 지도 확인은 약 3초에 끝났다.

최신화는 현재 저장된 로컬 원본을 대상으로 한다. 온라인 데이터 수집은 기존 수집 도구로 별도로 수행해야 한다. 자동 수집·예약 작업·게임 시작 시 생성은 추가하지 않았다.

## 미니맵 보완
기존 HUD는 전체 PNG를 1km 범위가 보이도록 확대했다. 80km 지도에서 원본 텍스처를 크게 늘려 픽셀 부족이 생길 수 있는 구조였다.

- 전체 지도 기본 화면은 합성 SVG를 사용한다.
- 확대 화면과 미니맵은 16×16 SVG 타일 중 현재 보이는 타일만 화면 해상도로 그린다.
- 타일 출력은 256~2048px, 표시기별 이미지 캐시는 최대 64MiB다.
- 도로·철로·해안선의 선폭을 화면 기준으로 제한해 확대 시 선형이 지나치게 두꺼워지는 문제도 보완했다.
- 화면 표시를 위한 SVG 텍스처 변환은 데이터 생성·수집과 별개이며 수동 갱신 요구를 변경하지 않는다.
- 준비된 타일이 없을 때는 기본 전체 지도 이미지를 유지한다.

## 자산 및 동시 작업 보호
결과는 지도별 `simple_map/revisions/<내용해시>/` 아래에 저장했다. 기존 지도 이미지를 삭제하지 않고 이전 경로를 `legacy_tactical_map`에 남겼다. 원본 이미지와 벡터 자료는 수정하지 않았다.

생성기 단일 작성자 잠금, 원본 파일 변경 감지, 지도 설정의 쓰기 전 비교와 공용 JSON 최신 내용 병합을 적용했다. 공용 자산 매니페스트에 모든 생성 파일의 SHA-256·bbox·고도 범위·실제 래스터 크기 또는 SVG viewBox를 기록하고 두 모듈 인덱스도 갱신했다.

원본 프로젝트의 `.godot`, `.import`와 에셋 프리뷰 실행파일은 수정하거나 재빌드하지 않았다. 게임에서는 기존 HUD의 지도 표시 부분에 SVG 타일 표시기를 연결했다.

## 확인 범위
- 6개 지도에 SVG 마스크 10개와 확대용 타일 256개씩 생성된 것을 확인했다.
- 분리된 임시 2D Godot 프로젝트에서 HUD 스크립트 파싱, 전체 SVG 표시, 확대 타일 로딩, 캐시 상한과 지도 이동을 확인했다.
- 실제 NVIDIA OpenGL Compatibility 렌더러의 표시 검사에서 런타임 오류가 없었고 `SIMPLE_MAP_PASS`가 출력됐다.
- 미니맵 예시와 전체 지도 표시 캡처는 `261004_SimpleMapDisplay.png`, 결과는 `261004_SimpleMapCheck.json`, 로그는 `261004_SimpleMapDisplay.log`다.
- 임시 프로젝트의 편집기 설정 저장 오류와 스캔 종료 경고는 별도로 로그에 남았다. 실제 표시 검사에는 오류가 없었다.
- 전체 3D 맵은 실행하지 않았다. 실제 게임 HUD의 장시간 이동·지도 전환에 대한 검증은 수행하지 않았다.

## 남은 데이터 범위
항구·항로 입력이 아직 없어 관련 정보는 표시되지 않는다. 140km 외곽 도로와 80km 밖 한국 철도는 현재 미수집 영역이 있다. 원본 DEM·수역의 단순화 및 해수 마스크가 없는 지도에서의 하구 분류는 근사다. 벡터 확대는 표시 품질을 높이며 원본의 공간 정밀도를 높이지는 않는다.

상세 입력 규약, 색상 설정과 명령은 `pipeline/processors/simple_maps/README.md`에 기록했다.
