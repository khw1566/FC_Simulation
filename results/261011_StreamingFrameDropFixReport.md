# 새 구역 진입 시 프레임 드랍 개선

이동하면서 새 구역이 나타날 때 멈춘다는 제보에 맞춰 스트리밍 경로를 수정했다. 계산 완료 후 지형·도로·건물 메시와 충돌체를 한 프레임에 붙이던 작업을 분산했다. 전체 지도 실행 없이 복사한 독립 프로젝트에서 변경 전후를 측정했다.

## 확인한 원인

- 지형 배열 계산은 작업 스레드에서 수행하지만, 큰 배열의 GPU 업로드는 메인 스레드에서 한 번에 실행됐다.
- 도로·건물 배치 앞에서만 2ms 예산을 확인했다. 배치 내부에서는 메시 수에 관계없이 생성이 계속됐다.
- 노반 타일을 읽고 해시를 검사하며 공간 색인을 만드는 동안 공유 잠금을 유지했다. 다른 스레드의 캐시된 높이 조회도 기다려야 했다.
- 밀집 노반의 균일 2m 세분화로 평탄한 부분까지 정점 수가 증가했다.
- 건물 충돌 형상 계산 완료 후에도 여러 충돌체의 장면 등록을 한 번에 처리했다.

## 적용 내용

- `stream_frame_budget.gd`: 지형·도로·건물·건물 충돌체 등록이 공유하는 프레임당 2ms, 최대 16회 예산을 도입했다. 시작한 개별 호출은 중간에 멈출 수 없으므로 2ms는 엄격한 상한이 아니다.
- `terrain_upload_pages.gd`, `terrain_mesh_upload.gd`: 48,000삼각형을 초과하는 지형은 작업 스레드에서 최대 16,000삼각형 페이지로 분할한다. 페이지마다 예산을 확인하고 업로드한다. 메시 하나의 표면 수가 64개를 넘으면 다음 메시를 사용한다.
- `terrain_chunk.gd`: 새 LOD 업로드가 모두 끝날 때까지 기존 지형을 표시한다. 캐시 재사용과 LOD 0 높이 격자 충돌을 유지한다. 이동 중 LOD 목표가 바뀌면 마지막 요청을 따른다.
- `prebaked_rail_baker.gd`: 대형 지형이 여러 메시로 나뉘어도 베이크 도구가 모든 메시와 충돌을 저장하도록 맞췄다. 이번 작업에서 베이크 결과물을 다시 생성하지는 않았다.
- `road_formation_grader.gd`: 타일 파일 읽기·해시·해석·색인 생성을 잠금 밖으로 옮겼다. 잠금은 캐시 조회와 완성된 항목 등록 때만 사용한다. 캐시 미스 자체의 파일 읽기는 요청한 스레드에서 수행한다.
- `road_earthwork_detail.gd`: 밀집 지형의 평탄한 부분은 세분화를 생략한다. 최대 변 길이 16m, 최소 2m를 사용하며, 중점·중심·좁은 도로 중심 표본의 높이 차이 0.12m를 검사한다. 이웃 삼각형과 만나는 경계의 잠재 분할 정점은 0.001m 기준으로 더 엄격하게 검사한다. 이 값은 표본 판정 기준이며 전 구간의 최대 오차를 보증하지 않는다.
- `road_batch_builder.gd`, `building_mesh_builder.gd`, `building_batch_assembler.gd`: 메시 사이에서 예산을 확인하고 다음 프레임으로 넘긴다. 건물은 청크 완성 후 표시하며, 동시에 완성되는 배치의 식별자가 충돌하지 않도록 고정한다.
- `building_collision_stream.gd`: 완료한 충돌 형상을 커서로 나눠 등록한다. 거리 이탈로 해제된 청크의 오래된 작업 결과를 버리는 기존 규칙을 유지한다.
- `performance_hud.gd`: F3 표시에 최근 개별 등록 작업 최대 시간과 드로우 호출 수를 추가했다.

## 변경 전후 측정

Godot 4.3, Vulkan Forward+, RTX 4070 SUPER, 320×180 창, VSync 해제 조건의 분리 측정이다. 게임 전체 프레임률 측정이 아니다. 아래 수치는 단일 실행에서 관찰한 최댓값이며 반복 실행 시 달라질 수 있다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 실제 밀집 512m 지형의 메인 스레드 업로드 호출 최대 | 22.307ms | 2.803ms |
| 도로 메시 2,048개 등록 부하: 동기 정지 / 분산 등록 중 최대 프레임 간격 | 93.556ms | 2.272ms |
| 다른 타일 12개를 읽는 동안 캐시된 높이 조회 최대 | 21.892ms | 0.038ms |
| 해당 지형 삼각형 수 | 375,369 | 236,082 |
| 해당 지형 정점 수 | 191,983 | 128,636 |

지형 표본은 노반 색인에서 선분 수가 가장 많은 타일이며 월드 중심 `(16640, -8960)`, 크기 512m, 포함 선분 1,576개이다. 변경 후 지형은 15페이지로 나뉘며 업로드 중 5번 프레임을 넘겼다. 지형의 백그라운드 계산은 약 12.3초로 여전히 무겁다. 큰 지형 청크 전체를 계산하는 시간은 이번 512m 측정으로 추정하지 않았다.

도로 부하는 각 배열이 삼각형 하나인 합성 메시 2,048개로 노드·메시 등록 비용을 분리했다. 실제 도로 전체의 복잡도나 FPS를 대표하지 않는다. 전체 배치 등록 시간은 93.920ms에서 173.375ms로 늘었지만, 129번 프레임을 넘기면서 한 프레임에 몰리던 작업을 분산했다. 실제 주행에서는 여러 프레임에 걸쳐 새 구역이 준비된다.

변경 전 지형의 `worker_ms` 필드는 업로드까지 포함한 기존 측정값이다. 변경 후에는 작업 스레드 계산 종료 시점에서 시간을 기록한다. 따라서 해당 필드의 차이를 정밀한 계산 속도 비교로 사용하지 않았다.

## 경량 확인 결과

- 지형 배열 분할에서 48,001개 삼각형의 순서, 위치, 법선, UV가 보존됐다. 65개 표면을 두 메시로 나누는 경계도 통과했다.
- LOD 계산·업로드 중 기존 지형 유지, 마지막 LOD 목표 반영, 캐시 전환, LOD 0 충돌 활성화, 작업 카운터 회수를 확인했다.
- 동시 건물 배치 두 개의 메시 128개, 그림자 생략 64개, 충돌체 128개의 생성과 거리 이탈 해제를 확인했다. 프레임당 등록 횟수 제한도 확인했다.
- 평탄한 표본의 불필요한 분할 생략과 곡선 경계의 세분화 유지를 확인했다.
- 기존 경사 지형 검사에서 도로 횡단 높이 차이 1.8m가 0m로 보정되고, 내부 15개 표본과 지형 투영 면적 16,384㎡가 유지됐다.
- 작은 도로 1,600m, 중간 도로 3,500m, 주요 도로 9,500m 표시 거리와 200m 여유 거리, 커브 경계 정점 보존 검사가 통과했다.
- 통합 관리자, HUD, 베이크 도구의 복사본을 파싱했다. 분리 GPU 실행 로그에서 스크립트 오류가 없었다. 베이크 도구 전체 실행은 하지 않았다.

## 색인과 적용 범위

- 루트와 Godot의 `module_index.json`, 전용 도구의 `module_index.json`을 갱신했다. 등록 모듈 25개, 최대 소스 길이 485줄이다.
- 이번 수정은 코드와 독립 검증 도구에 한정했다. 원본 에셋·지도 자료·생성 자산 매니페스트를 쓰지 않아 자산 색인은 재생성하지 않았다. 이번 코드 색인 작업의 보류 파일은 없다.
- 원본 프로젝트의 에디터·임포터와 전체 80km 지도는 실행하지 않았다. 전체 주행 FPS, 다른 구역의 최대 지연, 실행파일 재패키징은 이번 검증 범위에 포함되지 않는다.
