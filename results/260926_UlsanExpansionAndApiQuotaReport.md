# 울산 지형 확장(울산과학대학교 정밀맵 & 울산광역시 광역맵 분리) 및 외부 API 호출 제한 검토 보고서

## 1. 개요 및 목적
칸몬 해협(핵심 30km 도심)과 규슈 전역(100km 광역)을 분리 구성한 것과 동일하게, 울산 지형을 **울산과학대학교 서부캠퍼스 5km 정밀 실측 맵**과 **울산광역시 광역 맵(약 30~35km 권역)**으로 분리·확장하는 아키텍처를 수립하고, 공공데이터 및 외부 수집 API의 호출 제한과 초과 방지 대책을 사전 분석·검토합니다.

- **월드 스케일:** 5,000m × 5,000m (5km × 5km)
- **바운딩 박스 (BBox):**
  - South: 35.5220°N / North: 35.5670°N
  - West: 129.2279°E / East: 129.2831°E
- **주요 랜드마크/지형:** 울산과학대학교 서부캠퍼스, 울산대학교, 문수월드컵경기장, 무거동 시가지, 태화강 삼호교 인근
- **데이터 밀도:** VWorld 실측 건물 8,076동 전수 3D 배치, 정밀 16-bit 높이맵(2048x2048), 실측 도로망(512구간)

- **주요 랜드마크/지형:** 중구/남구/동구/북구/울주군 일대, 태화강 국가정원 전역, 울산항 및 방어진항, 현대자동차/현대중공업 국가산업단지, 영남알프스 자락(가지산/신불산 능선 일부)

## 3. 외부 API 호출 제한(Rate Limit) 및 수집 안정성 정밀 검토

파이프라인 구축 시 활용되는 3대 핵심 API의 공식 쿼터 제한 및 광역 데이터 수집 시 영향도를 분석하였습니다.

### 3.1 OpenTopography (Copernicus GLO-30 DEM API)
- **등록 키:** `data/api_keys.json` (`4e3ab1e43c5249eadad82f0e25fcad36`)
- **공식 호출 제한 규정:**
  - 1회 요청당 최대 면적 제한: $1,250,000 \text{ km}^2$ (COP30 전역 지원)
  - 요청 빈도(Rate Limit): 1분당 1~2회 요청 권장, 일일 호출 쿼터 존재 (일반 학술/개발 기준 일 수백 회).
- **광역 맵(35km × 35km, 약 1,225 $\text{km}^2$) 수집 시 위험도:** **[매우 낮음 (안전)]**
  - 35km × 35km 바운딩 박스는 OpenTopography 기준 단 **1회의 API 호출**로 GeoTIFF 고도 파일을 한 번에 수신 가능합니다.
  - 이미 기존 파일 캐싱 로직(`if os.path.exists and size > 1024: return`)이 작성되어 있어 불필요한 중복 호출이 원천 차단됩니다.

### 3.2 VWorld 디지털 트윈국토 실측 공간정보 (Data API 2.0 - `LT_C_SPBD`)
- **등록 키:** `data/api_keys.json` (`6D7B8894-BC4D-43C0-A5F3-9BA01DAD2E8A`)
- **공식 호출 제한 규정:**
  - **1회 요청당 공간 필터링 면적 제한:** **최대 10 $\text{km}^2$ 이하** (10 $\text{km}^2$ 초과 시 서버에서 `STATUS: ERROR` 및 요청 거부).
  - 1회 호출당 페이지 최대 레코드 수: `size=100` (100건).
  - 일일 총 호출 횟수: 기본 일 10,000 ~ 30,000건.
- **광역 맵(약 1,200 $\text{km}^2$) 수집 시 위험도 및 분석:** **[주의 - 분할 전수 요청 시 시간 소요 및 쿼터 고려 필요]**
  - 울산광역시 전역(1,200 $\text{km}^2$)을 VWorld의 10 $\text{km}^2$ 제한에 맞춰 전수 수집하려면 최소 120개~150개 이상의 그리드 셀로 분할해야 합니다.
  - 울산 전역의 건물 수는 약 20만~30만 동에 달하므로, 총 2,000~3,000회의 HTTP 페이지네이션 호출이 발생합니다.
  - **대응 및 해결 전략:**
    1. **정밀 맵(`ulsan_uc_west`):** VWorld 실측 풋프린트(8,076동)를 전수 유지하여 건물 형태와 층수를 실측 정밀 렌더링.
    2. **광역 맵(`ulsan_metro_wide`):** 35km 원거리 비행 시에는 VWorld 수십만 동을 모두 개별 메시로 그리면 GPU 오버헤드가 발생하므로, 도심 밀집 중심지(남구 삼산/무거/태화강변) 위주로 VWorld 건물을 추출하거나, OpenStreetMap(OSM Overpass) 대용량 건물 레이어 및 위성 2D 풋프린트 텍스처링 방식을 병행하여 API 쿼터를 안전하게 유지.

### 3.3 OpenStreetMap Overpass API (도로망, 수계, 행정구역)
- **공식 호출 제한 규정:**
  - 분당 요청 횟수 및 슬롯(Slot) 제한: 단일 IP당 동시 2개 슬롯 허용.
  - 1회 쿼리 런타임 제한: 60~180초 (대용량 단일 쿼리 시 504 Gateway Timeout 또는 429 Too Many Requests 발생).
- **광역 수집 시 위험도 및 대책:** **[보통 (기존 그리드 분할 캐싱 적용으로 완벽 통제 가능)]**
  - 이미 수집 모듈([building_collector.py](file:///c:/Users/work/Desktop/가상현실%20렌더링/pipeline/collectors/building_collector.py), [detailed_road_collector.py](file:///c:/Users/work/Desktop/가상현실%20렌더링/pipeline/collectors/detailed_road_collector.py))에 복수 미러 서버 로테이션(`mail.ru`, `overpass-api.de`, `kumi.systems`) 및 지연 시간(`time.sleep(1.0)`), 셀 단위 분할 수집, 로컬 캐시 재사용 로직이 적용되어 있어 차단 위험 없이 안정적으로 수집 가능합니다.
