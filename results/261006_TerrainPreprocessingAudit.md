## 도로 근거

- `pipeline/processors/heightmap_processor.py:45`에서 도로·건물 보정을 호출한다. 도로 마스크를 만든 뒤 주변 고도를 가우시안 스무딩하고 `min(원본 고도, 평활 고도) - 0.8m`로 절토한다. 건물 부지는 0.4m 낮춘다.
- `pipeline/run_pipeline.py:49`는 도로·건물 입력을 전달하지만 진입 함수는 `run_kanmon_pipeline()`이며 설정도 간몬이다.
- `results/260921_RoadTerrainCarvingReport.md`에는 간몬 도로 1,157개와 건물 972개를 적용해 높이맵을 재생성했다는 기록이 있다. 과거 실행 기록이며 현재 울산 산출물의 처리 이력을 증명하지는 않는다.
- `pipeline/processors/expand_ulsan_metro.py:56`은 60km·140km 높이맵을 표본화·접합한다. 이 코드에는 최신 울산 도로를 이용한 절토 호출이 없다. 입력 높이맵에 과거 보정이 포함됐을 가능성은 있으나 현재 보존된 메타데이터만으로 적용 범위를 확정할 수 없다.
- `pipeline/processors/rebuild_hydro_terrain.py`는 해안·수계 마스크와 해안 높이맵을 생성한다. 여기에도 도로 절토 단계는 없다.
- 9월 27일 울산 보고서의 `_apply_road_bed_flattening_and_smoothing()`은 당시 런타임 높이맵 보정이었다. 현재 코드에는 해당 메서드가 없다. 과거 보고서의 동작 설명을 현재 구현으로 해석하면 안 된다.
- 현재 `road_mesh_builder.gd`와 `road_surface.gdshader`는 도로를 표시 지형에 맞춘다. 이것은 도로 아래 지형을 사전에 고정하여 출력하는 처리와 다르다.

## 철도 근거와 자산 상태

`pipeline/processors/build_railway_alignment.py`는 현재 해안 보정 높이맵, 철도 네트워크, `config/railway_alignment.json`을 입력으로 다음 자료를 만든다.

- `assets/generated/railway/alignment.json`: 선로 종단 좌표와 터널 그룹.
- `assets/generated/railway/graded_heightmap_16bit.png`: 일반 철도 절성토 및 터널 갱구 절개 높이맵.
- `assets/generated/railway/tunnel_void.png`: 터널 통과 구역과 일반 선로 보조 마스크.

현재 확인:

- 세 출력 모두 공통 생성 매니페스트의 SHA-256과 실제 파일 해시가 일치한다.
- 세 출력에 기록된 원본 높이맵 해시도 현재 `ulsan_metro_80km/hydro/coastal_heightmap_16bit.png`와 일치한다.
- 현재 네트워크 777개 구간의 원본 좌표와 alignment의 보존 좌표가 777개 모두 일치한다.
- alignment에 저장된 설정과 현재 `config/railway_alignment.json`이 일치한다.
- 생성 보고서는 선로 777개, 터널 그룹 71개, 최대 종단 경사 약 3.5%를 기록한다. 이 값은 생성 통계이며 실제 주행 검증은 아니다.
- `terrain_chunk_manager.gd:223`은 사전 높이맵을 읽은 뒤에도 RailwayTerrainGrader를 구성한다. `terrain_chunk.gd:99`는 LOD0 철도 주변 삼각형을 추가 분할·보정한다. 충돌도 보정 메시에서 실행 시 생성한다.

높이맵만 사전 출력해도 좁은 철로 보정이 큰 LOD 삼각형에서 사라질 수 있어 추가 메시 보정이 도입됐다. `results/261004_RailLocalEarthwork.md`에 이 이유가 기록되어 있다. 따라서 현재 추가 보정만 삭제하면 철로 매몰이 재발할 수 있다.

## 원하는 구조로 전환할 때 필요한 범위

- 원본 지형·도로·철도·해안·공항 입력을 고정하고, 보정 순서를 명시한 하나의 생성 절차로 최종 지형을 만든다. 도로는 일반 지표 구간만 절토하고 교량·터널을 구분한다.
- 최종 높이맵과 함께 철로 주변의 **실제 표시 지형 메시를 청크·LOD별로 사전 출력**한다. 현재 재귀 세분화·법선 계산을 이 생성 단계로 옮긴다.
- 터널 개구부가 반영된 충돌 형상과 철도 노반도 같은 기준 지형에서 사전 출력한다. 고정된 선로 종단과 충돌 기준은 품질 선택으로 달라지지 않도록 한다.
- 실행 시에는 품질에 맞는 준비된 시각 자산을 읽고 거리별 배치·해제를 수행한다. 품질은 표시 상세도·범위를 선택하며 선로 설계 고도를 다시 계산하지 않는다.
- 현재 경량 높이맵은 RF 직접 읽기, 표준·고품질은 기존 PNG L8 읽기를 사용한다. 환경과 품질 사이의 고도 일관성을 위해 모든 품질의 실행용 고도 인코딩과 복원 규칙을 통일해야 한다.
- 생성 매니페스트에 높이맵뿐 아니라 도로·철도 입력, 설정, 생성기 버전, 좌표계, 고도 인코딩, 청크·LOD 규칙, 각 출력 해시를 기록한다. 동일한 완성 산출물을 여러 환경에서 배포·읽는 구조로 한다.
- 생성은 별도 작업으로만 수행하고 게임 시작 시 자동 재보정하지 않는다. 오래된 자산은 명시적으로 판별하고 마지막 정상 자산을 보존한다. 지원 Godot 버전과 렌더러에서 읽기·작은 지형 및 터널 조각을 확인한다.
- 산출물 고정은 지형 결과를 일정하게 만드는 방법이다. 장비별 저장장치·CPU·GPU 차이에 따른 로딩 시간까지 동일하게 보장하지는 않는다.
