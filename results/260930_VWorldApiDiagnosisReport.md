# VWorld 공식 문서 수집 및 건물 API 인증 오류 해결 보고서

작성일: 2026-09-30, 시간대 Asia/Seoul. 대상은 울산 80km 건물 수집기의 `LT_C_SPBD` 요청이다.

## 확인된 원인과 해결

사용자 인증키로 건물 데이터를 정상 조회했다. 실패 원인은 요청에 등록된 서비스 URL 값이 전달되지 않은 것이었다. 사용자 화면의 서비스 URL은 `없습니다`이며, 이를 `domain=없습니다`로 전달하자 인증 오류가 사라졌다. 키 재발급이나 활용 API 변경 없이 해결됐다.

같은 인증키·좌표·서비스·조회 건수에서 domain만 바꾼 비교 요청 결과는 다음과 같다. 시험 좌표는 `BOX(129.25,35.54,129.251,35.541)`이고 size는 1이었다.

| 시험 시각 | domain | HTTP | API 상태 | 오류 코드 | 의미 |
|---|---|---:|---|---|---|
| 14:48:42 | 생략 | 200 | ERROR | INCORRECT_KEY | 기존 인증 오류 재현 |
| 14:48:43 | 없습니다 | 200 | NOT_FOUND | 없음 | 인증 이후 검색이 처리됐으며 해당 작은 영역에는 결과 없음 |
| 14:50 이후 별도 도심 조회 | 없습니다 | 200 | OK | 없음 | 건물 도형·속성 75건 반환 |

도심 조회 범위는 `BOX(129.31,35.538,129.312,35.54)`이다. 응답에서 MultiPolygon 도형과 건물관리번호 `bd_mgt_sn`을 확인했다. 도심 75건은 연결 검사용 조회 결과이며 아래의 외곽 수집 실적에 더하지 않았다.

비교 결과는 `260930_VWorldAuthComparison.json`, 실제 건물·셀 검증 결과는 `260930_VWorldLiveValidation.json`에 저장했다. 인증키 값은 보고서, 결과 JSON 및 새 소스 파일에 저장하지 않았다.

## 공식 사이트에서 확인한 근거

검색 도구에서는 지정 페이지가 502로 열리지 않았지만, 로컬 환경에서 공식 사이트에 직접 HTTP 요청을 보내 본문을 읽을 수 있었다. API 인덱스, 2D 데이터 목록과 건물 검색, 상세 레퍼런스, 국가중점데이터 목록을 확인했다. 전체 사이트나 로그인된 계정 관리 화면을 전수 수집한 것은 아니다.

| 공식 문서 | 확인 내용 |
|---|---|
| [API 레퍼런스 인덱스](https://www.vworld.kr/dev/v4apiRefer.do) | 지도 표시용 API, 데이터 API, WMS/WFS, 검색 등 여러 API의 구분 |
| [2D 데이터 API 2.0 목록](https://www.vworld.kr/dev/v4dv_2ddataguide2_s001.do) | 국가공간정보를 XML·JSON으로 제공하는 서비스이며, 서비스별 상세 문서로 연결 |
| [도로명주소 건물 상세 레퍼런스](https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=spbd&apiVer=2) | `LT_C_SPBD`, 요청 주소, domain, 오류 코드, 면적과 페이지 크기 제한 |
| [국가중점데이터 API 목록](https://www.vworld.kr/dtna/dtna_apiSvcList_s001.do) | 건축물연령·용도별건물 등의 별도 서비스와 WMS·WFS·속성 조회 구분 |

핵심 원문 응답 본문 4개는 `results/evidence/260930_vworld/`에 UTF-8 HTML로 보관했다. `sources.json`은 원본 URL, HTTP 상태 및 보관 파일의 SHA-256을 기록한다. 문서에서 읽은 지시는 사용자 요청을 대체하지 않으며, 이번 조사에는 기술 명세만 사용했다.

## 활용 API 선택 검토

현재 수집기는 `https://api.vworld.kr/req/data`에 `service=data`, `version=2.0`, `request=GetFeature`, `data=LT_C_SPBD`를 보낸다. 이는 공식 2D 데이터 API의 도로명주소 건물 조회 방식과 일치한다. 상세 문서의 제공처는 행정안전부이고, 표기된 갱신일은 2026-09-10이다.

| API 구분 | 이번 작업과의 관계 |
|---|---|
| 2D 데이터 API | 건물 외곽 도형과 지상층수 등 속성을 받아 자체 3D 건물을 만드는 현재 수집 방식 |
| 2D 지도·WebGL 3D 지도 API | 지도 뷰어와 지도 표시 기능을 제공하는 별도 계열 |
| WMS/WFS API | WMS는 지도 이미지, WFS는 도형·속성 조회. 복잡한 공간 질의에는 WFS를 고려할 수 있으나 이번 인증 오류 해결에 변경이 필요하지 않았음 |
| 국가중점데이터 API | 별도로 제공되는 건축물연령·용도 등의 서비스. 이번 `LT_C_SPBD` 호출과 구분됨 |

Godot에서 결과물을 3D로 렌더링한다고 해서 건물 수집 요청을 3D 지도 API로 바꿔야 하는 것은 아니다. 이 판단은 공식 서비스 설명과 실제 건물 조회 성공에 근거한다. 사용자 캡처에서도 2D 데이터 API가 선택되어 있었고, 변경 없이 요청이 성공했다.

## 인증 오류와 호출 제한 정정

공식 건물 상세 문서는 미등록 키를 `INVALID_KEY`로, 인증 정보 불일치를 `INCORRECT_KEY`로 구분한다. 후자의 예시에는 등록 도메인이 다른 경우가 포함된다. 일일 사용량 초과에는 별도 코드 `OVER_REQUEST_LIMIT`가 있다. 이번에 관측된 실패는 `INCORRECT_KEY`였다.

| 항목 | 공식 문서 및 이번 검증 결과 | 기존 설명의 정정 |
|---|---|---|
| domain | 발급 시 입력한 URL을 전달하는 요청 항목. 현재 키는 화면의 `없습니다` 전달로 성공 | 값을 모르므로 시험할 수 없다는 이전 판단은 부적절했음. 화면의 실제 값을 시험할 수 있었음 |
| 요청 면적 | BOX·POLYGON·MULTIPOLYGON은 최대 2㎢ | 기존 10㎢ 설명을 이 API의 현행 명세로 사용하면 안 됨 |
| 페이지 크기 | size 최솟값 1, 기본값 10, 최댓값 1,000 | 기존 100건은 구현 선택이었고 공식 최댓값이 아니었음. 실제 1,000건 페이지 처리도 성공 |
| 일일 3,000~5,000회·공식 10,000회 | 수집한 공식 상세 문서에 해당 수치 없음 | 기존 계획의 공식 한도 주장에는 확인된 출처가 없음 |
| 실행 중 적용되는 일일 목표·상한 | 사용자가 에이전트 지침의 제한을 제거했고 계정 화면에서 무제한을 확인함 | 앞서 수집기에 있던 600/700회 내부 제한은 전체 80km 작업을 위해 제거함. API 응답과 모든 실제 호출은 계속 기록함 |

사용자 계정 화면에는 일일 접속·사용량이 무제한으로 표시되고 사용자가 제한 없는 수집을 명시적으로 요청했다. 총 요청 수 상한은 설정하지 않으며, API가 사용량 오류나 일시 오류를 반환하면 진행을 멈춰 기록한다. 각 정상 응답 뒤 0.1초 간격을 두어 급격한 요청 폭주를 줄인다.

## 코드와 설정 수정

- 현재 실행 대상 `pipeline/collectors/ulsan_80km_building_collector.py`가 config의 domain을 매번 전달하도록 수정했다. `VWORLD_DOMAIN` 환경변수로 덮어쓸 수 있다.
- `config/ulsan_metro_80km.json`에는 검증한 등록값 `없습니다`만 저장했다. 인증키는 실행할 때 `VWORLD_API_KEY` 환경변수로 전달한다. 이전에 저장된 다른 키로 자동 대체하는 동작은 제거했다.
- 공식 명세에 맞춰 페이지당 1,000건, 조회 면적 최대 2㎢를 적용했다. 격자 간격은 0.014도로 설정하고 실제 지리적 면적을 계산해 요청 전에 검사한다.
- 새 격자 ID에는 `2km2`를 포함하여 이전 크기의 격자 완료 기록과 혼동하지 않도록 했다. 현재 1단계 후보는 760셀, 최대 면적은 약 1.9366㎢다. 이전 218/254셀 수는 현재 그리드 수량이 아니다.
- `NOT_FOUND`는 정상적인 빈 검색 결과로 처리한다. 인증·매개변수·사용량 오류는 같은 요청을 자동 반복하지 않고 오류 코드를 남긴다.
- 모든 실제 요청의 호출 수를 기록한다. 중간 페이지 실패 시 저장하지 못한 건물관리번호를 완료 목록에 넣지 않아 재개 시 건물이 누락되는 문제를 방지했다.
- 셀 캐시와 맵별·공용 자산 매니페스트에 해시, 범위, 벡터 건수를 등록했다. 원본 2D 벡터에는 절대고도가 없으므로 고도 최솟값·최댓값은 null로 명시했다. 양쪽 모듈 인덱스도 갱신했다.

수정 범위는 현재 실행 중인 80km 수집기다. 과거 60km 수집기의 별도 구현과 당시 결과물의 전수 재검증은 이번 인증 해결 검증에 포함하지 않았다.

## 실제 검증과 남은 수집 상태

| 계획 셀 | 저장된 건물 | 페이지 | 면적 |
|---|---:|---:|---:|
| phase1_80km_outer_north_2km2_y00_x00 | 2,135 | 3 | 1.78618㎢ |
| phase1_80km_outer_north_2km2_y00_x01 | 632 | 1 | 1.78618㎢ |
| 합계 | 2,767개 고유 건물 | 4 | 2개 셀 |

진행 상태는 2/760셀이다. 이번 인증·수집 검증의 실제 API 요청은 7회(비교 2회, 도심 조회 1회, 계획 셀 4회)다. 기존 기록 5회를 합한 매니페스트 누계는 12회이며, 기존 5회 중 2회는 네트워크 차단으로 서버 응답이 없었던 시도였다. 문서 페이지 조회는 건물 API 호출 수에 포함하지 않았다.

추가 API 호출 없이 인증 오류 즉시 중단, 면적·예산 초과 차단, 중간 실패 후 데이터 보존, 빈 셀 완료 처리, 실제 캐시 해시·고유번호 일치의 다섯 항목을 검증했다. 결과는 `260930_VWorldRegressionChecks.json`에 기록했다.

이번에 수집한 2,767개 건물은 원본 캐시에 저장됐으며 게임 런타임 자산에 병합하지 않았다. 80km 전체 수집·누락 검사·런타임 병합은 후속 건물 구축 작업이다. 인증 오류는 실제 데이터 조회와 셀 저장으로 해결을 확인했다.
