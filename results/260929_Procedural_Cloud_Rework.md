# 절차적 구름 재구성

## 적용 내용

- 메인 월드의 구름 관리자를 `procedural_cloud_manager.gd`로 교체했다. 기존 기상 관리자와 품질 설정의 호출 방식은 유지한다.
- 적운은 크기가 다른 둥근 응결 덩어리와 평평한 밑면을 합성한다.
- 층운은 넓은 연속층과 작은 밀도 변화를 사용한다. 기존의 모든 유형에 공통으로 적용하던 구형 외곽 마스크를 사용하지 않는다.
- 권운은 고도 6,500~8,500m 부근에서 바람 방향으로 늘어진 섬유와 굽은 결을 합성한다.
- 뇌우의 적란운은 적운 구조 위에 넓은 모루 모양을 추가한다.
- 기상의 적운·층운·권운·적란운 비율과 색을 보간한다. 기본 설정에서 약 12초 후 목표의 95%에 도달한다. 맑음 전환도 즉시 숨기지 않고 서서히 소멸한다.
- 기존 7가지 날씨 조합을 유지하고 층적운 항목은 새 층운 계층으로 연결했다. 구름 이외의 비·안개·태양 밝기 전환 방식은 기존 방식이다.
- 품질 ‘끄기’ 상태에서 날씨를 변경해도 구름이 다시 켜지지 않도록 활성화와 품질 상태를 분리했다. 기상 시스템을 다시 켜면 현재 기상을 재적용한다.

## 성능 예산

| 품질 | 최대 표시 볼륨 | 적운·층운·적란운 샘플 | 권운 샘플 |
|---|---:|---:|---:|
| Ultra | 16 | 18 | 6 |
| High | 12 | 12 | 6 |
| Medium | 8 | 8 | 6 |
| Laptop / Low | 5 | 5 | 5 |
| Off | 0 | 0 | 0 |

- 48×32×48 절차적 노이즈 텍스처 하나와 박스 메시 하나를 공유한다. 날씨 전환으로 노이즈나 메시를 다시 만들지 않는다.
- 기존 픽셀별 Worley 이웃 탐색과 중첩 광원 레이마칭 대신 샘플당 1~2회 노이즈 텍스처 조회와 높이 기반 음영을 사용한다.
- 구름 출구 면만 렌더링해 앞·뒤 면의 이중 적분을 줄인다. 화면 깊이로 적분 구간을 잘라 지형 뒤 구름이 앞으로 비치는 것을 방지하도록 구성했다.
- 재질 매개변수는 최대 초당 10회 갱신한다. 바람 이동과 기상 보간은 매 프레임 수행하며 순환 경계에서는 투명도를 낮춘다.
- 비행 후류는 근처 구름에만 적용하고 이탈 시 초기화한다. 낮은 품질에서는 비활성화한다.
- 맑음 전환이 완료되면 갱신을 중단한다. 끄기 상태도 처리와 렌더링을 중단한다.

## 파일 역할

- `scripts/weather/cloud_pool_factory.gd`: 고정 시드 기반 초기 분포, 유형별 크기와 고도, 공유 노이즈 생성.
- `scripts/weather/procedural_cloud_manager.gd`: 날씨 혼합, 품질 상한, 바람, 순환 배치, 후류 갱신.
- `shaders/cloud_density.gdshaderinc`: 구름 종류별 밀도 함수.
- `shaders/procedural_cloud_volume.gdshader`: 깊이 가림과 제한된 볼륨 적분.
- 기존 `cloud_cluster_manager.gd`와 `volumetric_cloud.gdshader`는 보존하되 메인 월드에서는 사용하지 않는다.

## 확인 범위

- 실제 게임 실행, 셰이더 컴파일 확인, GPU 프레임 시간 측정은 이번 작업에서 수행하지 않았다.
- 표의 수치는 코드에 설정한 상한이며 FPS 개선 측정값이 아니다. 넓은 층운이 화면을 채우면 저사양에서도 픽셀 처리 비용이 남는다.
- 투명 볼륨 간 겹침은 Godot의 오브젝트 단위 투명 정렬을 사용한다. 완전한 대기 산란이나 구름 자체 그림자 시뮬레이션은 아니다.
