# 지도 시작 품질 선택 및 로딩 경량화 반영

작성일: 2026-10-06. 계획서 `261006_LoadingOptimizationPlan.md`의 시작 품질·초기 범위·철도 생성·높이맵 읽기 중심 개선을 반영했다. 전체 울산 맵 실행과 원본 Godot 임포터 실행은 하지 않았다.

## 반영 내용

- 지도 선택 화면에 경량·표준·고품질 선택을 추가했다. 신규 및 품질 저장값이 없는 사용자는 경량으로 시작하고, 명시적으로 선택한 품질은 저장한다. 실행 중 세션 품질은 다음 지도 시작까지 고정한다.
- 경량에서 MSAA·그림자를 끄고 지형 LOD 해상도를 64/32/16으로 낮춘다. 표준·고품질은 128/64/32를 사용한다. 도로 절삭 간격과 도로 셰이더 보간도 같은 실제 격자 해상도를 사용한다.
- 울산 80km의 청크 배치는 11×11을 유지한다. 경량은 상세 지형 거리 4.5km, 중간 지형 거리 12km로 줄이며 철도 재귀 세분화는 LOD0에만 적용한다. 세분화 기준은 경량 40m, 표준 20m, 고품질 10m다.
- 건물·도로 최초 준비 반경을 경량 2km, 표준 3.5km, 고품질 5km로 분리했다. 후속 표시 반경은 각각 3/5/8km이며 선행 여유는 0.5/1/1.5km다. 지형·벡터 초기 준비 후 조작을 허용하고 주변 확장 작업은 로딩 화면 종료 후 진행한다.
- 벡터 인덱스의 주기적인 재검색은 플레이어가 250m 이상 이동했을 때 진행한다. 첫 시작 후 확장 요청은 별도로 유지한다.
- 철도 논리 노선과 표시 청크를 분리했다. 최초 반경 안의 청크부터 생성하고 주변 표시 범위를 확장한다. 가까운 선로만 침목·전차선·야간 조명을 구성하고 상세 범위 밖에서는 간략 선로를 사용한다. 이탈 청크는 여유 반경 밖에서 해제하고 이동 시 간략·상세 표현을 교체한다.
- 기존 철도 역사·특수 교량·열차 경로 구성은 유지한다. 전체 일반 선로 메시를 시작 전에 모두 생성하던 작업을 제거했다.
- 실제 사용할 높이맵을 사전 로딩에서 확정하여 원본 해안 높이맵과 철도 보정 높이맵의 이중 읽기를 제거했다. 지형·도로가 GPU 높이 텍스처 하나를 공유한다.
- 울산 경량 높이맵을 2816×2816으로 사전 생성했다. 원본이 변경되거나 파생 자산이 없으면 원본 경로로 복귀한다. 이 경우 경량 높이 축소는 이미지 작업 스레드에서 수행한다.
- 배경 지형과 공단의 초기 작업은 로딩 화면 종료 뒤로 미뤘다.
- 이미지 스레드 대기 중에도 240초 제한을 검사하고, 실패·취소된 세션의 뒤늦은 결과가 씬 전환에 사용되지 않도록 했다.
- 이미지 읽기, 씬 읽기, 지형 높이 준비, 청크 생성, 첫 준비 완료 시간을 실행 로그에 기록한다.

## 정적 작업량 비교

현재 울산 벡터 인덱스의 배치 중심과 반경을 이용한 후보 수다. 실제 생성량은 건물 대체 영역 등 기존 필터에 따라 달라진다. 실행 시간 측정 결과가 아니다.

| 최초 준비 범위 | 건물 배치 / 건물 수 | 도로 배치 / 도로 수 | 총 배치 |
| --- | --- | --- | --- |
| 기존 9.5km | 1,067 / 63,866 | 409 / 2,792 | 1,476 |
| 경량 2km | 147 / 9,061 | 60 / 439 | 207 |
| 표준 3.5km | 255 / 15,208 | 115 / 810 | 370 |
| 고품질 5km | 463 / 27,977 | 184 / 1,287 | 647 |

경량 최초 후보 배치 수는 약 86% 감소했다. 이후 주변 스트리밍으로 범위를 넓히므로 지도 전체의 자료를 삭제한 것은 아니다.

## 경량 고도 자산과 터널 공간 인덱스

- 실행용: `godot_project/assets/generated/terrain_quality/ulsan_metro_80km/light/heightmap_c14275644bfbb424_2816.rf32z`, 16,805,386바이트(약 16.03MiB).
- 확인용 16bit PNG: 같은 디렉터리의 `heightmap_c14275644bfbb424_2816.png`, 7,852,028바이트(약 7.49MiB). 게임은 이 확인용 PNG를 높이맵으로 읽지 않는다.
- 실행용 RF 데이터는 little-endian 폭·높이 헤더와 zlib 압축 float32 정규화 고도로 구성된다. 복원 시 약 30.25MiB이며 기존 5632 RF 이미지의 약 121MiB보다 작다.
- Godot 4.3의 현재 PNG 읽기는 원본과 경량 16bit PNG를 모두 L8로 반환했다. 경량 실행용 자산은 직접 RF로 복원하여 8bit 양자화를 피한다. 표준·고품질의 원본 PNG 읽기는 기존 동작을 유지한다.
- 터널 공간 인덱스: `godot_project/assets/generated/terrain_quality/ulsan_metro_80km/tunnel_buckets_e922b121149b04f1.json`, 19,260바이트, 512m 공간 셀 516개.
- 터널 인덱스는 실제 마스크 B 채널의 모든 유효 픽셀을 포함하도록 생성했다. 노선 메타데이터의 터널 목록만으로 추정한 인덱스는 전체 마스크를 포함하지 못하여 채택하지 않았다.
- 터널 인덱스가 누락되거나 마스크 크기·수정 시각이 달라지면 기존 전체 마스크 검사로 복귀한다. 터널 충돌 처리 자체를 생략하지 않는다.
- 원본 높이맵·수계 마스크·터널 마스크는 수정하거나 축소하지 않았다. 경량 높이맵의 공항 평탄화는 기존 런타임 처리를 유지한다.

## 자산·모듈 색인 및 환경

- 원본 에셋 삭제 없이 경량 RF 래스터, 확인용 PNG, 품질 매니페스트와 터널 공간 인덱스를 추가했다. 공통 `assets/generated/manifest.json`에 해시·bbox·고도 범위·해상도·원본 참조를 등록했다.
- `ASSET_INDEX_GUIDE.md`와 `asset_inventory.py`에 `terrain_quality` 분류 및 `.rf32z` 역할을 함께 추가했다.
- 지정 명령 `.venv_campus/Scripts/python.exe pipeline/indexer/build_asset_index.py`를 수동 실행했다. 최종 전체 색인은 28,618파일이며 보류 0개다. `asset_index.json`과 `ASSET_INDEX.md` 갱신을 완료했다.
- 품질 모델, 철도 표시 스트림, 경량 파생 생성기를 루트와 Godot 모듈 인덱스에 등록했다. `building_road_manager.gd`는 588줄이며 주요 책임을 추가로 덧붙이지 않았다.
- 지정 가상환경 설정에 남아 있던 다른 사용자 `C:/Users/work` 경로 때문에 Python 실행이 실패했다. `.venv_campus/pyvenv.cfg`의 실행기 경로를 설치된 번들 런타임으로 복구했으며 원본 설정은 `results/quality_check/pyvenv_campus_original.cfg`에 보존했다. 새 패키지를 설치하지 않았다.
- 검증 전용 `.venv_optimization`을 별도로 만들었다. 프리뷰 실행파일과 캐시는 변경하지 않았고 다른 게임·에이전트 프로세스를 종료하지 않았다.

## 남은 최적화 항목

- 도로 배치의 이동 이탈 해제와 도로·터널 중복 판정 소유권 분리.
- 정밀 지형 충돌을 LOD0 청크 전체와 분리하여 더 작은 이동 반경에서 스케줄링.
- 소형 건물을 생성 전에 생략하고 이동 시 재생성하는 별도 건물 상세 단계.
- 단일 큰 건물·도로 작업의 내부 분할과 배열 계산 작업 스레드 전환.
- 공항·문화유산·특수 철도 교량·역사 모델의 거리별 생성, 공단 GLB 충돌의 사전 생성.
- 배경 지형 자체의 작은 파생 표본과 GPU 제출 예산, 다른 지도용 사전 경량 자산.
- 표준·고품질 원본 높이맵의 PNG L8 읽기를 피하는 별도 정밀 실행용 자산.
- 전체 맵 실행을 요청받은 경우 동일 장비에서 cold/warm 로딩과 시각·충돌 정합성 확인.

기존 계획서의 후속 항목을 모두 완료한 상태는 아니다. 이번 반영은 시작 품질 선택과 가장 큰 초기 생성량을 줄이는 실행 가능한 첫 변경이다.
