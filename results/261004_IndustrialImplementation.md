# 울산 절차 공단 구현 결과
사용자가 지정한 방식에 따라 울산 본항·온산항 주변의 안전한 육지 후보 두 곳을 선정하고 울산 80km 월드에 연결했다. 구역은 게임용 생성 영역이며 실제 공단의 확정 경계나 실제 시설 배치를 뜻하지 않는다.

## 생성 결과
내부 도로 12개, 필지 20개, 주요 설비 43개, 부착 배관 랙 7개를 생성했다. 설비별 진입로는 내부 도로에 연결한다.

| 구역 | 유형 | 설비 수 | 경도 범위 | 위도 범위 |
|---|---|---:|---|---|
| 울산 본항 주변 | 일반 제조 | 29 | 129.364639~129.377927 | 35.509010~35.519822 |
| 온산항 주변 | 석유화학 | 14 | 129.357351~129.370639 | 35.456822~35.467634 |

본항 구역에는 박공·평지붕·톱니지붕 공장과 부속 냉각·연통을 배치했다. 온산 구역에는 저장탱크·LPG 구형 탱크·공정 탑·냉각 설비를 배치했다. 공정 탑은 카탈로그의 연결 포트에 배관 랙을 맞췄다. 조명 리그와 배출구가 정의된 설비는 해당 표시 효과도 연결한다. 야간 조명은 발광 표시를 사용하며 개별 실제 광원은 기본 비활성이다.

## 안전 영역과 지표 부착
수계 주변 20m, 저고도 수면 후보, 경사 8도 초과, 기존 건물 주변 4m, 철도 주변 35m, 주요 도로·교량·터널, 문화재 주변 300m, 공항 활주로 주변 550m를 제외한다. 기존 지도 시설을 삭제하지 않고 빈 공간을 사용한다.

설비 중심점 대신 회전·축척·부착 배관을 포함한 전체 footprint를 검사한다. 기존 도로 점유 면적을 피하고 기존 도로 ID와 접속점을 보존한다. 내부 도로는 연결된 그래프를 유지하며 도로 종단 경사 8% 이하, 설비 기초 고저 차 3.5m 이하를 적용한다.

런타임에서는 실제 표시 중인 지형 LOD 높이를 조회해 설비를 올리고 기초를 지표 아래까지 연장한다. 기초에는 충돌체를 부착한다. 생성 도로는 기존 도로 메시 생성기와 지형 LOD 보정을 공유한다. LOD 텍스처를 재사용해 기존 도로의 높이 보정 연결도 유지한다.

## 월드와 설정
`main_world.tscn`에 별도의 `IndustrialZoneManager`를 연결했다. 울산 80km 맵에서만 배치 데이터를 읽는다. 600m 청크로 묶고 2.6km 이내에서 상세 모델, 9km 이내에서 단순 MultiMesh 윤곽을 표시한다. 상세 모델은 가까운 순서로 프레임당 최대 두 개 생성한다.

설정의 `절차 생성 공단 표시`를 끄면 생성 도로·원거리 윤곽을 숨기고 상세 모델·충돌체·연기를 해제한다. 다시 켜면 거리 기준으로 복구한다. 선택은 사용자 설정 파일에 저장된다.

신규 Python 모듈과 Godot 모듈을 양쪽 `module_index.json`에 등록했다. 구역 마스크·배치 데이터의 해시, bbox, 고도 범위와 해상도는 전용 및 공통 매니페스트에 기록했다.

전체 에셋 색인을 명시적 가상환경의 `pipeline/indexer/build_asset_index.py`로 수동 갱신했다. 최종 23,226개 파일, 보류 0개다. 이번 구역 계열의 산출물 10개에 대해 전용·공통 매니페스트의 SHA256 일치도 확인했다.

## 확인 범위
독립 구조 검사에서 두 구역의 설비 43개와 도로 12개에 대해 전체 footprint, 기존 시설 및 설비 간 중첩, 도로 연결, 배관 포트 정합성을 확인했다. 실패 항목은 없다.

전체 맵 대신 원본 GLB와 실제 배치 데이터를 사용하는 가벼운 OpenGL 구역 장면을 실행했다. 본항 29개·온산 14개 상세 모델 로드, 원거리 전환, 설정 끄기·복구·저장과 재로드를 확인했다. 실제 지형 높이를 사용하는 독립 장면에서 도로·설비 렌더링을 확인했다. 전체 맵에서의 장시간 운행·성능·다른 기능과의 종합 검증은 수행하지 않았다.

```powershell
& '.\.venv_campus\Scripts\python.exe' pipeline/indexer/build_asset_index.py
```
