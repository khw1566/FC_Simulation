# 선박 배치 및 운항 구현

- 울산 80km 지도: 울산 본항, 온산항, 방어진항, 진하항 주변에 선박 6종 총 10척을 배치했다. 원본 크기와 Y=0 수면 기준을 보존했다.
- 간몬 해협 및 규슈 광역 지도: 모지항과 시모노세키항 주변에 각각 7척을 연결했다.
- 항포구에서 90초 정박 후 외해로 이동하고 20초 대기한 뒤 복귀한다. 선종별 속도는 2.5~6m/s이며 초기 주기를 분산했다. 실제 AIS·항로·접안 지점·수심 데이터가 아닌 게임용 왕복 운항이다.
- 해수 격자를 선체 반대각선+15m 이상 침식하고 단순화 경로의 모든 구간을 재검사했다. 선박 방향 전환 중에도 선체가 해안을 침범하지 않도록 여유를 확보했다. 선박 간 충돌이나 물리 부력은 구현 범위에 포함하지 않았다.
- ESC → 환경 설정 → 일반 / 컨트롤 → 선박 배치 및 운항에서 켜고 끈다. 끄면 인스턴스를 제거하고 프레임 처리를 중지하며, 켜면 중지한 운항 시점부터 다시 배치한다. 설정은 `user://settings.cfg`에 영구 저장한다.
- 플레이어 14km 밖은 표시하지 않으며 원본 GLB 모델은 종류별로 공유 캐시한다. 새로운 기능은 독립 모듈로 분리했다.
- 경상도 140km는 현재 물 마스크에서 안전한 해상 경로를 확인할 수 없어 제외했다. 해수면을 비활성화한 내륙 지도에도 선박을 생성하지 않는다.
- 전체 맵은 실행하지 않았다. 경량 장면에서 원본 GLB 6종 로드, 수면 높이, 왕복 주기, 이동 연속성, 체크박스 즉시 적용, 별도 테스트 파일 저장 및 재로드를 검증했다. 실제 사용자 설정은 변경하지 않았다.
- 항로 결과: `261004_VesselNavigationValidation.json`. 런타임 결과: `261004_VesselRuntimeValidation.json`. 설정과 원본 모델 미리보기: `261004_VesselSettings.png`, `261004_VesselModels.png`.
- 항포구 위치 및 선종별 속도, 정박 시간은 `config/vessel_traffic.json`에서 조정 후 `pipeline/processors/vessels/build_traffic.py`로 재생성한다. 양쪽 모듈 인덱스 및 생성 자산 해시 매니페스트를 갱신했다.
