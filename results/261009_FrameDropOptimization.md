# 비행 중 프레임 드랍 원인 분석 및 에셋 스트리밍 최적화
작성일: 2026-10-09. 정적 코드 분석으로 원인을 찾고 수정했다. 전체 울산 맵 실행과 원본 프로젝트 임포터 실행은 하지 않았으며, 수정 스크립트는 임시 프로젝트에서 구문·동작만 검사했다.

## 1. 원인
### P0: 건물 충돌체 생성 시 GPU 버퍼 역읽기(비행 중 반복 끊김)
- `building_collision_stream.gd`는 0.05초마다 플레이어 2.25km 안의 건물 청크 하나에 `mesh.create_trimesh_shape()`를 호출했다.
- Godot 4의 `ArrayMesh`는 CPU 사본을 보관하지 않으므로 이 호출은 렌더링 서버에서 정점 버퍼를 다시 읽는다. 메인 스레드가 GPU와 동기화되며 멈춘다.
- 청크 메시 하나는 최대 1,200동, 수만 개 삼각형이다. 같은 1.5km 공간 셀에도 배치별 청크 노드가 여러 개 있어, 이동하는 동안 거의 매 갱신마다 이 작업이 반복됐다.
- 고고도 비행 중에도 반경 기준만 사용하여 쓰이지 않는 충돌체를 계속 만들었다.

### P0: 도로 배치가 해제되지 않고 누적(시간이 갈수록 FPS 하락)
- `vector_data_stream.gd`는 건물만 이탈 반경 밖에서 해제했다. 도로 배치(`roads_loaded`)는 한 번 만들면 해제하지 않았다.
- 도로 메시는 지형 고도 전체를 덮는 `custom_aabb`를 사용하고 표시 거리 제한이 없었다. 비행할수록 렌더링 대상이 계속 늘었다. 울산 전체 도로 배치는 1,517개이며 배치마다 메시 인스턴스가 최대 5개 생긴다.

### P1: 도로 배치의 메인 스레드 처리
- 도로 배치 파일 읽기, SHA-256 검증, JSON 해석이 비행 중에도 메인 스레드에서 동기 실행됐다.
- 중복 판정 키(점 좌표 문자열 연결)와 메시 계산, `SurfaceTool.commit()`이 메인 스레드에서 실행됐다.
- 교량 충돌체도 `create_trimesh_collision()`으로 GPU 버퍼를 다시 읽었다.

### P1: 공단·선박 GLB 최초 로딩
- 설비·선박 종류마다 처음 시야에 들어올 때 메인 스레드에서 GLB 해석, 씬 생성, 모든 메시의 trimesh 충돌체 생성(GPU 역읽기 포함)을 수행했다.
- 읽기에 실패한 경로는 캐시하지 않아 재시도가 반복될 수 있었다.

### P2: 기타
- 철도 청크마다 새 재질 3개와 표시등 재질·`GradientTexture2D`를 만들었다. 재질 수만큼 렌더 배치가 나뉘고 텍스처 생성이 반복됐다.
- 건물 가시성 갱신이 0.05초마다 모든 청크에 `get_node_or_null("MinorBuildings")` 경로 조회를 했다.

### 에셋 로딩이 느린 원인
- 건물 배치는 읽기 작업과 메시 계산 작업을 차례로 기다리며 한 번에 한 배치만 처리했다. 배치마다 최소 2~3프레임이 필요했다.
- 로딩 화면에서는 건물 배치를 메인 스레드에서 하나씩 동기 생성했고, 도로는 도로 하나마다 프레임 예산 검사를 거쳤다.

## 2. 수정 내용
### 건물 충돌
- `building_mesh_builder.gd`: 메시 생성 시 이미 계산된 삼각형 정점 배열을 `collision_faces` 메타로 보관한다.
- `building_collision_stream.gd`: 보관 정점으로 `ConcavePolygonShape3D`를 작업 스레드에서 만들고, 완성된 형상만 메인 스레드에서 붙인다. 동시 작업은 2개로 제한한다.
- 지면 위 600m보다 높이 날 때는 새 충돌체를 만들지 않는다. 기존 충돌체는 거리 기준으로만 해제한다.
- 해제 후 곧바로 재요청된 청크의 이전 결과는 일련번호로 구분해 버린다. 관리자가 트리에서 빠질 때 남은 작업을 회수한다.

### 도로
- 신규 `road_batch_builder.gd`: 메타데이터 보정, 중복 판정 키 계산, 도로·보행로·비포장로·터널·교량 메시 배열과 교량 충돌 형상을 작업 스레드에서 계산한다. 메인 스레드는 대체 판정과 노드 조립만 수행한다.
- 도로 배치도 건물과 같은 이탈 반경에서 해제한다. 해제 시 중복 판정 키와 터널 구간을 함께 되돌려 재진입 시 다시 생성된다. 방파제 배치는 유지한다.
- 포장도로는 건물 표시 거리 + 4.5km(스트림 해제 반경과 동일), 보행로·비포장로는 건물 표시 거리까지만 그린다.
- `building_road_manager.gd`는 도로 메시 생성 코드를 위임하여 545줄에서 454줄로 줄었다.

### 스트리밍 병렬화
- `vector_data_stream.gd`: 후보 배치를 동시에 여러 개 준비한다. 비행 중에는 `코어 수/2 - 1`(1~4), 로딩 화면에서는 `코어 수 - 1`(1~8)개를 병렬로 처리한다.
- 읽기·검증·해석·메시 계산은 작업 스레드, 대체 판정과 노드 생성만 메인 스레드에서 한다. 노드 생성은 프레임 예산(비행 중 2ms, 로딩 중 8ms) 안에서 나눠 붙인다.
- 프레임 예산 기준 시각을 프레임 번호로 갱신하여 여러 작업이 같은 프레임 예산을 공유한다.
- 이동으로 재정렬이 필요하면 새 요청은 멈추고, 이미 시작한 배치는 끝까지 마친다.

### 공단·선박 모델
- 신규 `threaded_scene_cache.gd`: 키별 PackedScene을 작업 스레드에서 한 번만 만든다. 실패한 키도 기록하여 같은 실패 읽기를 반복하지 않는다.
- `industrial_asset_factory.gd`, `industrial_zone_manager.gd`: 준비되지 않은 설비는 대기열 끝으로 돌리고 준비된 모델만 배치한다.
- `vessel_model_factory.gd`, `vessel_world_manager.gd`: 선박 모델 준비 전에는 건너뛰고 다음 프레임에 다시 확인한다. 검사 도구용 동기 호출(`instantiate(entry)`)은 유지한다.

### 철도·가시성
- `railway_track_builder.gd`, `railway_night_lighting.gd`: 색상·크기별 재질과 표시 텍스처를 공유한다.
- `building_batch_assembler.gd`, `building_road_manager.gd`: 청크 정보에 소형 건물 노드를 보관하여 경로 조회를 제거했다.

## 3. 검증
- 임시 프로젝트(세션 스크래치 디렉터리)에 `scripts`, `shaders`, `project.godot`만 복사해 검사했다. 원본 `.godot`, `.import`, 에셋은 변경하지 않았다.
- 수정·신규 스크립트 13개 컴파일: 실패 0개. 검사 스크립트: `results/frame_drop_check/check.gd`.
- 동작 검사 15항목: 실패 0개. 검사 스크립트: `results/frame_drop_check/behavior.gd`.
- 동작 검사 범위: 도로 종류별 배열 분리, 교량 형상 면 수 일치, 건물 정점 메타 보관, 고고도 충돌 생략, 작업 스레드 충돌체 부착·원거리 해제·재요청 중복 방지, 모델 캐시 대기·준비·실패 기록, 철도 재질 공유.
- 임시 프로젝트에 로딩 화면 씬이 없어 자동 로드 오류가 출력됐고, 종료 시 헤드리스 더미 렌더러의 메시 저장소 경고가 출력됐다. 이번 변경과 무관하다.
- 실제 GPU 렌더링, 80km 맵 FPS·최대 프레임 시간, 로딩 시간은 측정하지 않았다. 개선 폭을 수치로 주장하지 않는다. 게임 내 F3 FPS 표시의 "최대 ms"로 확인할 수 있다.

## 4. 자산·모듈 색인
- 에셋 파일을 추가·수정·삭제하지 않았으므로 에셋 색인(`build_asset_index.py`)은 실행하지 않았다.
- `module_index.json`, `godot_project/module_index.json`에 `RoadBatchBuilder`, `ThreadedSceneCache`를 등록하고 `vector_data_stream.gd`, `building_collision_stream.gd` 항목을 갱신했다.

## 5. 남은 항목
- 철도 청크(`TrackBuilder.build`, 노반)는 여전히 메인 스레드에서 청크당 한 프레임씩 생성한다. 같은 방식으로 배열 계산을 작업 스레드로 옮길 수 있다.
- 공단 GLB 충돌체는 작업 스레드로 옮겼지만 여전히 렌더링 메시를 다시 읽는다. 파이프라인에서 충돌 형상을 미리 만들면 이 동기화도 없앨 수 있다.
- 건물 재질은 다각형 감김 방향이 일정하지 않아 양면 렌더링을 유지했다. 표준·고품질에서 그림자를 켜면 건물 그림자 비용이 크다.
- 건물 대체 판정(`BatchAssembler.group`)은 랜드마크 노드 변환을 읽으므로 메인 스레드에 남겼다.
