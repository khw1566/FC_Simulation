# 데스크탑 프레임 저하 개선 및 FPS 표시

- 실제 실행 장치: Godot 4.3 Forward+ / Vulkan / NVIDIA GeForce RTX 4070 SUPER.
- 기존 설정은 이미 MSAA·그림자·구름이 꺼져 있었다. 외장 GPU 선택 실패나 구름 품질만으로 원인을 설명할 수 없었다.
- 코드에서 지도 진입 후 `_refresh(-1.0)`로 전체 건물·도로 구역을 계속 생성하는 동작을 확인했다. 이는 메인 스레드 생성 작업과 상주 자산을 지속해서 증가시키는 병목이다. 노트북과 데스크탑의 동일 조건 비교는 수행하지 않았다.

## 수정

- 지도 전체 사전 생성을 플레이어 주변 반경 생성으로 교체했다. 이동 중 주변 구역을 다시 확인한다.
- 가시 반경에 여유 거리를 더한 범위 밖의 건물 배치를 해제하고, 재접근하면 다시 생성한다. 도로는 중복 생성·터널 충돌 정보 보존을 위해 유지한다.
- 로딩 중 생성 예산은 8ms, 진입 후에는 2ms로 분리했다. 개별 메시 생성은 이 예산을 초과할 수 있으므로 엄격한 프레임 시간 상한은 아니다.
- 설정 UI 초기화는 신호 없이 적용해 초기값 설정 중 저장과 기상 재적용을 막았다.
- 독립 PerformanceHUD에서 FPS, 평균 및 최대 프레임 시간을 0.5초마다 표시한다. 벽시계 프레임 간격을 측정하며 GPU 처리 시간 자체를 의미하지 않는다.
- 기본 표시 켬. F3와 ESC → 설정 → 그래픽 → FPS 및 프레임 시간 표시로 전환하며 재실행 후에도 유지한다. 표시를 끄면 측정 처리도 멈춘다.
- 루트·Godot 모듈 인덱스를 갱신했다.

## 검증

- Godot 에디터 가져오기 검사 종료 코드 0.
- 실제 Vulkan 1280×720, 울산 80km 시작 위치 검사: 로딩 22.619초, 상주 배치 1,476개 / 전체 10,895개.
- 로딩 종료 후 정지 상태 3초 측정: 평균 60.16 FPS, 최대 프레임 간격 29.877ms. 해당 설정과 위치의 짧은 측정이며 수정 전 대비 향상률을 의미하지 않는다.
- 정지 상태 배치 수 유지, FPS 표시 갱신, 표시를 끈 동안 처리 중단, 중복 진입 차단, 메뉴 복귀, 로딩 취소 복구 모두 통과.
- 결과: `results/map_loading_validation.json`, 로그: `results/261003_render_check.log`.
- 로딩 중 최대 프레임 간격은 1,054ms였다. 최초 자산·지형 준비 비용은 남아 있으며 이동 중 지형 LOD 변경과 개별 도로 생성에서도 추가 지연이 발생할 수 있다.
- 기존 이미지 직접 로드 경고와 종료 시 ObjectDB 누수 경고가 출력됐다. 이번 FPS/스트리밍 검사 실패는 없었다.
- FPS 관련 엔진 API 참고: [Godot Engine 4.3 공식 문서](https://docs.godotengine.org/en/4.3/classes/class_engine.html).
