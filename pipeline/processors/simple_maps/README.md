# 수동 계층 지도 갱신
게임 실행과 분리된 도구다. 최신 로컬 DEM·수역·도로·철도·건물 자료로 계층 마스크를 만들고, 색상을 입혀 전체 SVG와 확대용 SVG 타일을 합성한다. 게임은 준비된 파일을 읽고 화면에 표시하며 원본 수집이나 지도 생성을 실행하지 않는다.

## 수동 실행
프로젝트 루트 PowerShell에서 실행한다.

```powershell
./pipeline/update_map_images.ps1
```

등록된 6개 지도 전체를 갱신한다. 특정 지도만 선택할 수도 있다.

```powershell
./pipeline/update_map_images.ps1 -Maps ulsan_uc_west,ulsan_metro_80km
./pipeline/update_map_images.ps1 -Force
```

- 프로젝트의 `.venv_campus/Scripts/python.exe`를 명시적으로 사용한다.
- 원본과 설정이 그대로면 생성을 건너뛴다. 색상만 바뀌면 저장된 형상·마스크 데이터를 재사용해 합성한다.
- 네트워크 재수집은 하지 않는다. 기존 수집 도구로 원본을 갱신한 다음 위 명령을 실행하면 최신 로컬 자료가 반영된다.
- 자동 실행, 예약 갱신, 게임 시작 시 갱신은 없다. 게임 실행 중 업데이트한 파일을 자동 적용하는 기능도 추가하지 않았다.

## 색상과 단순화
`config/simple_vector_maps.json`에서 색상, 해상도, 산지 고도 구간, 대로 분류 및 소형맵 기준을 조절한다.

| 계층 | 기본 색상 | 표현 |
|---|---|---|
| 해안선 | 청록 | 실제 해안 벡터 우선, 없으면 해수 마스크 외곽 |
| 대로 | 주황 | 고속도로·간선도로 분류 또는 폭 14m 이상 원본 |
| 철로 | 보라 | 수집된 철도 중심선 |
| 강 | 하늘색 | 하천 면과 중심선 |
| 호수 | 파랑 | 호수·저수지 면 |
| 항구 | 빨강 | 별도 입력한 항만 영역 또는 지점 |
| 항로 | 초록 | 별도 입력한 항로 선 |
| 산지 | 갈색 | DEM의 150·350·700·1100m 이상 고도 영역을 중첩 |
| 건물 | 회색 | 10km 이하 소형맵의 건물 윤곽 |

바다는 옅은 하늘색, 육지는 밝은 중립색을 사용한다. 게임 UI 테마는 변경하지 않는다. 항구·항로의 입력 자료가 없으면 해당 마스크는 비워 두며 추정 항로를 만들지 않는다.

## 결과 구조
지도마다 `godot_project/assets/maps/<지도ID>/simple_map/revisions/<내용해시>/`에 생성한다.

- `map.svg`: 전체 계층을 색상으로 합성한 SVG. 외부 PNG를 삽입하지 않은 벡터 경로로 구성한다.
- `masks/*.svg`: 정보별 흑백 벡터 마스크 10개. 바다 배경도 독립 계층으로 포함한다.
- `masks/*.png`: 동일 계층의 8-bit 마스크. 외부 합성 도구에서 활용할 수 있다.
- `tiles/*.svg`: 16×16개로 나눈 확대용 벡터 타일.
- `tiles.json`: 타일 목록 규칙, 색상과 계층별 형상 수.
- `preview.png`: 빠른 확인용 합성 이미지. 게임 확대 표시의 원본으로 사용하지 않는다.
- `manifest.json`: 파일별 SHA-256, 바운딩 박스, 고도 범위 및 실제 벡터/래스터 해상도.

생성된 지도는 각 `map_meta.json`의 `tactical_map`, `preview_image` 및 타일 인덱스 참조에 연결된다. 공용 자산 매니페스트와 모듈 인덱스도 갱신한다. 원래 지도 경로는 `legacy_tactical_map`에 보존하고 기존 이미지를 삭제하지 않는다.

## 미니맵 표시
전체 SVG는 기본 전체 화면 지도에 사용한다. 확대 화면과 미니맵은 현재 보이는 타일만 SVG에서 화면 해상도로 그린다. 전체 지도 PNG를 수십 배 늘리는 방식의 픽셀 확대를 피한다.

- 타일 출력 해상도는 256~2048px 범위에서 표시 크기에 맞춘다.
- 도로·철도·해안선의 표시 선폭은 확대 시 제한해 과도하게 화면을 덮지 않게 한다.
- 화면 밖 타일은 읽지 않으며 표시기별 이미지 캐시는 최대 64MiB다.
- 표시할 새 타일이 준비되기 전에는 기본 전체 SVG 텍스처를 유지한다.
- 화면 표시를 위해 SVG를 GPU용 텍스처로 변환하는 과정은 데이터·마스크 갱신과 별개다.

## 항구·항로 입력 규약
다음 경로에 EPSG:4326 경위도 좌표의 GeoJSON FeatureCollection을 저장한다. 경로는 설정 파일에서 바꿀 수 있다.

```text
data/raw/navigation/<지도ID>/harbors.geojson
data/raw/navigation/<지도ID>/shipping_routes.geojson
```

- 항구는 Point, Polygon 또는 MultiPolygon을 사용한다.
- 항로는 LineString 또는 MultiLineString을 사용한다.
- 좌표는 `[경도, 위도]` 순서다. 데이터는 지도 bbox로 잘라 표시한다.
- 파일을 추가·갱신한 뒤 수동 갱신 명령을 다시 실행하면 해당 마스크와 합성 지도에 반영된다.
- 현재 작업 중인 선박 운항 생성기와 기존 `vessels/traffic.json`은 수정하지 않았다.

## 자료 범위와 한계
- 지도 그림은 현재 저장된 원본 범위만 표현한다. 갱신 명령은 실제 세계의 변화나 온라인 자료 최신성을 자동 확인하지 않는다.
- 140km 지도에서 도로 원본은 기존 소형맵과 80km 권역 자료를 활용한다. 80km 밖의 미수집 도로를 임의로 생성하지 않는다.
- 한국 철도는 기존 80km 수집 영역을 사용한다. 그 밖의 미수집 철도는 추가 원본이 필요하다.
- 대로 분류가 없는 소형맵은 저장된 폭을 사용하므로 실제 도로 등급과 일치한다고 보장하지 않는다.
- 고도·수역은 원본 래스터를 단순화한 벡터 영역이다. 표시 확대가 원본 자료의 공간 정밀도를 높이지는 않는다.
- 해수 마스크가 없는 지도는 경계와 연결된 수역을 해수 후보로 사용하므로 하구의 바다·강 분류는 근사다.

## 동시 작업 보호
지도 생성기는 단일 작성자 잠금을 사용한다. 각 원본의 크기·수정 시각과 지도 설정의 변경 여부를 확인한 뒤 결과를 게시한다. 공용 JSON은 최신 내용을 읽어 필요한 항목만 병합하고 쓰기 직전 변경을 확인한다. 새 결과는 별도의 내용 해시 폴더에 저장하며 원본 `.godot`, `.import`와 에셋 프리뷰 실행파일은 수정하지 않는다.
