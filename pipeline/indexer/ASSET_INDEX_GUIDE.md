# 에셋 인덱스 작성 지침
모든 에셋 추가·수정·삭제 작업은 생성기 실행 후 아래 수동 색인을 갱신하고 결과를 작업 보고에 남긴다. 게임 실행 시에는 갱신하지 않는다.

## 갱신 명령
프로젝트 루트에서 PowerShell로 실행한다.

```powershell
& '.\.venv_campus\Scripts\python.exe' pipeline/indexer/build_asset_index.py
```

## 필수 산출물
- `godot_project/assets/asset_index.json`: 전체 파일 경로, 분류, 역할, SHA256, 크기, 수정 시각, 리비전, 기존 매니페스트의 공간·고도·해상도 메타데이터.
- `godot_project/assets/ASSET_INDEX.md`: 분류별 집계와 모델·씬 목록.
- 각 생성 에셋 계열의 `manifest.json`, `catalog.json` 및 README: 생성기의 책임으로 갱신한다. 중앙 색인은 기존 매니페스트를 대체하지 않는다.
- 새 생성기·색인 모듈은 `module_index.json` 또는 해당 패키지 `__init__.py`에 노출한다.

## 분류 체계
- 산업·공단: 공장, 증류, 연통, 저장 탱크, 배관, 송전, 냉각, 격납고, 크레인.
- 공단 구역 마스크 (`industrial_zones`): 사용자 지정 공단의 16bit 구역 ID, 수계 제외·1차 허용 마스크 및 구역 카탈로그. 지도 bbox와 픽셀 크기, 경계 원본 해시, 초안/확정 상태를 기록한다. 마스크만으로 실제 공단 확정 경계나 배치 안전성을 주장하지 않는다.
- 같은 계열의 절차 배치 데이터에는 도로 진입점의 기존 도로 ID, 연결 그래프, 필지, 설비 전체 footprint와 변환, 기초 바닥 높이, 배관 랙 연결 포트, 야간 조명 참조를 기록한다. 자동 후보는 게임용 후보임을 명시한다. 생성 결과 해시와 지도 bbox를 매니페스트에 기록하며 원본 산업 모델은 보존한다.
- 플랜트 탑·배관·연기 (`industrial_plant`): 연통·공정 탑, 3열 연결 랙, 연기·증기 프리셋과 조립 예제. 연결 포트의 규격·위치·방향과 연기 배출구를 계열 카탈로그에 기록한다.
- 공단 야간 조명 (`industrial_lighting`): 원본 에셋에 부착되는 광원·발광 리그. 원본 에셋 키, 발광 장치 수, 실제 광원 수, 그림자·거리 소거·주야간 기본값을 계열 카탈로그에 기록한다. GLB만 로드할 때는 조명이 포함되지 않는다.
- 교통: 선박, 철도, 철도교, 철도터널, 보행교, 교량, 공항, 역사·역세권.
- 환경·시설: 발전소, 문화유산, 지형 타일, 지형·지도 기반, 원경. 공통 매니페스트와 번역 자료는 공통 에셋 메타데이터로 분류한다.
- 광역 원경 고도 (`horizon`): `.f32`는 little-endian float32 표고 미터를 행 우선으로 기록한다. 해상도·Web Mercator bbox·출처·해시를 계열 매니페스트에 기록하며, RGB 고도 텍스처의 인코딩은 카탈로그에 명시한다. 수평 표본 간격을 원본 측량 정밀도로 표현하지 않는다.
- 표시·자료: 지도, UI, 셰이더. 모델·씬·이미지·벡터·지리 데이터·문서는 파일 역할로 별도 구분한다.
- 둔치 생태 구역 (`taehwagang_ecozones`): 대상 지도 bbox 격자의 8bit 구역 ID 라벨, 구역별 바닥 혼합 스플랫(RGBA 2장), 512px 반복 바닥 텍스처, 구역별 규칙 격자 식생 인스턴스(`scatter_instances.json`, 월드 미터·지도 중앙 원점). 원천 둔치 마스크 해시, OSM 캐시 시각, 구역 면적, 레이어별 인스턴스 수를 카탈로그에 기록한다. 경도 범위·기준 다각형으로 정한 구역은 추정이며 현장 식생도가 아니다(`status=generated_estimate`).
- 억새·갈대 (`silvergrass`): 억새 군집·억새 군락 타일·갈대 군락 3종 × 3 LOD와 원경 카드. 계열 공통 `vegetation_batch_factory.gd`로 64m 청크 MultiMesh 묶음, 그림자 없음.
- 새 계열은 `asset_inventory.py`의 CATEGORIES와 이 지침을 함께 갱신한다. 알 수 없는 계열은 기타로 기록하고 보고한다.

## 기록 원칙
- 실제 데이터와 범용 절차 모델을 구분한다. 조사하지 않은 위치·고도·해상도·검증 상태는 추정하지 않고 null 또는 미확인으로 유지한다.
- GLB와 해당 Godot 씬은 같은 모델의 표현 파일이다. 파일 수를 에셋 종류 수로 부르지 않는다.
- 지도 리비전은 이력으로 분류한다. 최신 수정 시각만으로 실제 활성 리비전을 판단하지 않는다.
- 현재 범위는 `godot_project/assets`와 `godot_project/shaders`다. 외부 원천 데이터, 프리뷰 캐시, 임포터 캐시, 게임 씬은 범위 밖이다.

## 동시 작업 및 완료 기준
- 원본은 읽기 전용으로 조사한다. 조사 도중 바뀌거나 잠긴 파일은 pending으로 남기고 기존 색인 항목이 있으면 유지한다.
- 중앙 색인은 단일 작성자 잠금과 임시 파일 교체로 기록한다. 다른 프로세스의 잠금을 강제로 삭제하지 않는다.
- 공유 매니페스트와 모듈 인덱스의 비대상 항목을 보존한다. 동시 변경 오류는 최신 파일을 읽어 재실행한다.
- 작업 완료 보고에는 추가·수정·삭제한 에셋, 갱신 명령, pending 수, 확인한 범위를 기록한다. pending이 있으면 미완료 항목을 명시한다.
- 경량 구조 확인을 사용하며 전체 맵 실행이나 프리뷰 실행파일 재빌드는 에셋 색인의 필수 절차가 아니다.
