# 에셋 인덱스 작성 지침
모든 에셋 추가·수정·삭제 작업은 생성기 실행 후 아래 수동 색인을 갱신하고 결과를 작업 보고에 남긴다. 게임 실행 시에는 갱신하지 않는다.

## 갱신 명령
프로젝트 루트에서 PowerShell로 실행한다.

```powershell
& '.\.venv_campus\Scripts\python.exe' pipeline/indexer/build_asset_index.py
```

## 필수 산출물
- `godot_project/assets/asset_index.json`: 전체 파일 경로, 분류, 역할, SHA256, 크기, 수정 시각, 리비전, 기존 매니페스트의 공간·고도·해상도 메타데이터.
- `godot_project/assets/ASSET_INDEX.md`: 분류별 집계와 모델·씬 목록.
- 각 생성 에셋 계열의 `manifest.json`, `catalog.json` 및 README: 생성기의 책임으로 갱신한다. 중앙 색인은 기존 매니페스트를 대체하지 않는다.
- 새 생성기·색인 모듈은 `module_index.json` 또는 해당 패키지 `__init__.py`에 노출한다.

## 분류 체계
- 모듈형 도로·보행로 (`road_assets`): 차선별 차도, 다양한 보행로, 곡선·분기·폭 전환·턱 낮춤, 독립 경계 부재와 노면 표시다. 1단위=1m, Y축 높이, 표면 기준 높이, 총 차선 수, 갓길 폭, 접속 Marker3D 위치·바깥 방향·단면 규격, 로컬 AABB와 삼각형 수를 카탈로그에 기록한다. 같은 단면의 서로 다른 표면을 혼합할 수 있다. 분리 가능한 차선 표시와 혼합 조립 예제를 독립 에셋으로 기록한다. 실제 지리 bbox는 null이며 고도는 로컬 Y 범위다. 게임·지도·기존 도로 렌더러에 자동 적용하지 않는다. GLB와 대응 씬을 같은 에셋으로 센다. 생성 결과의 해시를 전용 및 공통 매니페스트에 등록한다.
- 같은 `road_assets` 계열의 혼합 교차로는 중앙부·진입부·횡단 표시를 분리한다. 접속점마다 주도로 또는 분기도로 차선 수를 기록한다. 보행 데크의 광장 개구 폭, 하부 프레임 높이, 분리형 직선·곡선·경사 난간, 지지대 상단 기준과 높이, 경사로의 양 끝 높이를 기록한다. `extension_set`으로 증분 에셋을 구분하고 기존 기본 모델을 보존한다. 데크와 기존 보행로는 같은 walk 단면을 사용한다. 추가 조립 예제와 생성 해시는 기존 전용·공통 매니페스트에 병합한다.
- 도로 확장의 경량 표현은 `detail_profile=low_poly_flat_v1`로 기록한다. 외부 텍스처 없이 단색·큰 구획선을 사용한다. 곡선의 내부 세분화는 줄이되 끝 접속점·방향·폭·높이를 보존한다. 원본 삼각형 수와 파일 크기 비교는 작업 보고에 남긴다.
- 철로 사전 보정 테스트 (`prebaked_rail_test`): 실제 울산 소구역에서 추출한 사전 보정 지형 3품질, 고정 충돌, 선로·노반·터널 PackedScene이다. 원본 해시, 구역 bbox, 고도 범위, 원본 래스터 해상도와 각 품질 그리드 및 철로 세분화 간격, 생성 Godot 버전을 매니페스트에 기록한다. 실행 프로젝트에는 원본 고도·마스크·철도 JSON·생성기를 넣지 않는다. 원본이나 생성기가 바뀌면 수동 재생성하며 실행 중 자동 갱신하지 않는다.
- 품질별 지형 파생 자산 (`terrain_quality`): 원본을 보존하고 품질·지도별로 생성한 16bit 높이맵. 원본 경로·해시·파일 크기·수정 시각, bbox, 고도 범위, 해상도, 인코딩·축소 규칙·보정 정책을 매니페스트에 기록한다. 변경된 원본을 감지하면 이전 파생 자산 대신 원본 읽기로 복귀한다. 공통 생성 매니페스트에도 등록하고 게임 실행 시 생성기를 실행하지 않는다.
- 같은 계열의 터널 충돌 공간 인덱스는 실제 RGBA 터널 마스크의 B 채널 유효 픽셀을 전부 포함하는 보수적 셀 목록이다. 원본 마스크 해시·크기·수정 시각과 셀 폭을 기록하며 원본 변경 또는 인덱스 누락 시 전체 마스크 검사로 복귀한다.
- 경량 실행용 `.rf32z`는 little-endian uint32 폭·높이 8바이트 헤더 뒤에 zlib 압축된 행 우선 float32 정규화 고도를 저장한다. Godot PNG 읽기의 8bit 변환을 피하기 위한 형식이다. 같은 이름의 16bit PNG는 확인용 이미지이며 실행용 래스터와 역할을 구분하여 기록한다.
- 산업·공단: 공장, 증류, 연통, 저장 탱크, 배관, 송전, 냉각, 격납고, 크레인.
- 공단 구역 마스크 (`industrial_zones`): 사용자 지정 공단의 16bit 구역 ID, 수계 제외·1차 허용 마스크 및 구역 카탈로그. 지도 bbox와 픽셀 크기, 경계 원본 해시, 초안/확정 상태를 기록한다. 마스크만으로 실제 공단 확정 경계나 배치 안전성을 주장하지 않는다.
- 같은 계열의 절차 배치 데이터에는 도로 진입점의 기존 도로 ID, 연결 그래프, 필지, 설비 전체 footprint와 변환, 기초 바닥 높이, 배관 랙 연결 포트, 야간 조명 참조를 기록한다. 자동 후보는 게임용 후보임을 명시한다. 생성 결과 해시와 지도 bbox를 매니페스트에 기록하며 원본 산업 모델은 보존한다.
- 플랜트 탑·배관·연기 (`industrial_plant`): 연통·공정 탑, 3열 연결 랙, 연기·증기 프리셋과 조립 예제. 연결 포트의 규격·위치·방향과 연기 배출구를 계열 카탈로그에 기록한다.
- 공단 야간 조명 (`industrial_lighting`): 원본 에셋에 부착되는 광원·발광 리그. 원본 에셋 키, 발광 장치 수, 실제 광원 수, 그림자·거리 소거·주야간 기본값을 계열 카탈로그에 기록한다. GLB만 로드할 때는 조명이 포함되지 않는다.
- 모듈형 항구 (`harbor_assets`): 방파제·부두·호안·말뚝·등대·어업용 및 컨테이너 크레인·단위 테트라포드·컨테이너·기반시설. `detail_profile=harbor_low_poly_flat_v1`, 무광 단색 인덱스 GLB, 외부 텍스처 없음. Y=0은 상판 완성면 또는 시설 바닥이다. Marker3D -Z 바깥 방향, 포트 profile·폭·위치·방향과 기초 깊이·상단 높이·로컬 AABB·시설 작동 범위를 카탈로그에 기록한다. 상판은 수평, 기초와 지지말뚝은 DEM 표본에 맞춰 독립 선택한다. 지리 bbox는 null, 고도는 로컬 Y 범위다. 실제 항구 좌표·표고·수위를 추정하거나 게임에 자동 적용하지 않는다. GLB와 대응 씬은 하나의 모델이며 조립 예제는 별도로 센다. 단위 테트라포드는 MultiMesh 반복 사용을 권장하고 기본 충돌은 생성하지 않는다.
- 교통: 선박, 철도, 철도교, 철도터널, 보행교, 교량, 공항, 역사·역세권.
- 철로·교량의 정적 경량 씬은 `detail_profile=rail_bridge_low_poly_v1`로 기록한다. 궤간·접속 Marker3D·광원·기존 충돌 형상과 계단·징검다리 보행판을 보존한다. 단색 무광 재질과 성긴 반복 부재를 사용하며 외부 텍스처 없이 야간 표시의 내장 그라데이션만 8×8로 축소한다. `triangles`는 MultiMesh의 인스턴스 수까지 곱한 렌더 삼각형 수이며 `triangle_count_method=mesh_faces_times_instances`로 계산법을 기록한다. `connections_preserved`, `collision_geometry_preserved`를 구조 확인 결과로 기록한다. 재생성은 독립 프리뷰 작업 공간에서 수행하며 게임·지도·실행 생성기를 변경하지 않는다.
- 커스텀 공항·성곽·역사·산업시설·플랜트·선박·발전소의 경량 표현은 `detail_profile=custom_low_poly_flat_v1`로 기록한다. 원본 실행 생성기와 지리 배치는 보존하고 격리 복사본에서 재생성한다. GLB는 중복 위치·평면 법선을 공유하는 인덱스 메시이며 미사용 재질을 제외한다. `triangle_count_method=gltf_primitive_indices`는 GLB 인덱스 수를 3으로 나눈 값이다. 대응 씬과 GLB는 같은 모델이며 모델 수를 중복 계산하지 않는다. 배관 포트·선박 수면 기준·조립 변환·조명·연기 설정과 기존 충돌을 유지하며 현재 로컬 AABB·해시·삼각형 수를 전용 및 공통 매니페스트에 기록한다. 외부 텍스처 없이 단색 무광 재질을 사용한다.
- 환경·시설: 발전소, 문화유산, 지형 타일, 지형·지도 기반, 원경. 공통 매니페스트와 번역 자료는 공통 에셋 메타데이터로 분류한다.
- 광역 원경 고도 (`horizon`): `.f32`는 little-endian float32 표고 미터를 행 우선으로 기록한다. 해상도·Web Mercator bbox·출처·해시를 계열 매니페스트에 기록하며, RGB 고도 텍스처의 인코딩은 카탈로그에 명시한다. 수평 표본 간격을 원본 측량 정밀도로 표현하지 않는다.
- 표시·자료: 지도, UI, 셰이더. 모델·씬·이미지·벡터·지리 데이터·문서는 파일 역할로 별도 구분한다.
- 새 계열은 `asset_inventory.py`의 CATEGORIES와 이 지침을 함께 갱신한다. 알 수 없는 계열은 기타로 기록하고 보고한다.

## 기록 원칙
- 실제 데이터와 범용 절차 모델을 구분한다. 조사하지 않은 위치·고도·해상도·검증 상태는 추정하지 않고 null 또는 미확인으로 유지한다.
- GLB와 해당 Godot 씬은 같은 모델의 표현 파일이다. 파일 수를 에셋 종류 수로 부르지 않는다.
- 지도 리비전은 이력으로 분류한다. 최신 수정 시각만으로 실제 활성 리비전을 판단하지 않는다.
- 현재 범위는 `godot_project/assets`와 `godot_project/shaders`다. 외부 원천 데이터, 프리뷰 캐시, 임포터 캐시, 게임 씬은 범위 밖이다.

## 동시 작업 및 완료 기준
- 원본은 읽기 전용으로 조사한다. 조사 도중 바뀌거나 잠긴 파일은 pending으로 남기고 기존 색인 항목이 있으면 유지한다.
- 중앙 색인은 단일 작성자 잠금과 임시 파일 교체로 기록한다. 다른 프로세스의 잠금을 강제로 삭제하지 않는다.
- 공유 매니페스트와 모듈 인덱스의 비대상 항목을 보존한다. 동시 변경 오류는 최신 파일을 읽어 재실행한다.
- 작업 완료 보고에는 추가·수정·삭제한 에셋, 갱신 명령, pending 수, 확인한 범위를 기록한다. pending이 있으면 미완료 항목을 명시한다.
- 경량 구조 확인을 사용하며 전체 맵 실행이나 프리뷰 실행파일 재빌드는 에셋 색인의 필수 절차가 아니다.
