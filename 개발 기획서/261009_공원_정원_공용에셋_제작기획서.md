# 공원·정원 공용 에셋 제작 기획서

작성일: 2026-10-09. 프로젝트: FC_Simulation. 상세 후보 목록: `results/261009_ParkAssetList.md`.

## 1. 목표와 제작 범위

태화강 국가정원의 잔디광장·대숲 가장자리·초화원·자연주의 화단·수변 녹지를 구성할 공용 에셋 체계를 만든다. 동일 자산을 도시공원·하천변 산책로·근린 녹지에 재사용할 수 있어야 한다. 첫 목표는 넓은 공간을 적은 종류의 자산으로 자연스럽게 구성하는 것이다.

제작물을 세 층으로 나눈다.

- 지표: 잔디·맨흙·자갈·낙엽처럼 면적으로 보이는 부분. 지형 표면과 마스크를 우선 사용한다.
- 반복 입체 자산: 풀·초화·관목·대나무·수목처럼 군락이나 개체로 배치할 부분. LOD와 청크 배치를 기본으로 둔다.
- 시설과 조합: 경계·길·벤치·조명·휴게 공간. 접속 규격과 배치 기준점을 공유한다.

이번 기획은 모델 제작과 독립 프리뷰까지다. 실제 국가정원 전역의 식재 좌표 확정, 기존 지형·수계 수정, 게임 자동 배치 연결, 사람·동물 AI, 시설 작동 시뮬레이션은 별도 범위다. 아직 새로운 모델은 생성하지 않았다.

## 2. 조사에서 확인한 공간과 제작 판단

| 공간 유형 | 공용 자산 구성 | 제작 판단 |
|---|---|---|
| 대숲과 대숲 진입부 | 기존 대나무 + 낮은 풀 + 맨흙 길 + 경계 + 안내판 | 대나무 모델 재제작보다 숲 가장자리와 통로 여백 조합 우선 |
| 초화원·계절 화단 | 낮은 꽃무리 + 키 큰 꽃대 + 잎 군락 + 경계 | 개별 꽃보다 높이·색·개화 상태가 다른 군락 우선 |
| 자연주의 화단 | 관상용 풀 + 다년초 + 마른 꽃대 + 성긴 맨흙 | 꽃이 없는 시기에도 실루엣이 남는 구성 필요 |
| 잔디·그늘 휴게 공간 | 지표 잔디 + 기존 활엽수 + 벤치 + 길 | 넓은 바닥을 작은 풀 메시로 모두 덮지 않음 |
| 수변 가장자리 | 키 큰 수변 식생 + 낮은 풀 + 돌 + 보행 경계 | 종·수위·실제 식재 위치는 후속 조사 후 적용 |
| 행사·가족 공간 | 기존 천막·정자·피크닉 세트 + 표지 + 휴지통 | 기존 시설물 재사용; 놀이터·부스는 선택 확장 |

앞의 공간 분류는 울산시 공식 정원 소개와 시설 안내를 참고했다. 오른쪽 제작 판단은 실제 식재 설계도나 현장 수량을 복원한 것이 아닌 게임 자산 구성 제안이다. 출처는 문서 마지막에 정리한다.

## 3. 기존 자산 재사용 정책

- 수목: trees의 broadleaf/slender/conifer/shrub과 기존 LOD 체계를 사용한다. 일반 활엽수 모델을 근거 없이 느티나무·벚나무 등 실제 종으로 재명명하지 않는다.
- 대나무: bamboo의 단일·4줄기·9줄기 군락과 청크 배치 규격을 유지한다. 통로에 잎이 침범하지 않는 가장자리 조합을 추가한다.
- 시설: garden_furniture의 정자·등받이 벤치·평벤치·소형 천막·행사 천막·피크닉 테이블을 우선 사용한다. 근경 132~704, 원경 36~156 삼각형이라는 현재 README 기록을 초기 비용 기준으로 참고한다.
- 보행: road_assets의 기존 보행로·데크·경사로·난간과 같은 단면·접속 규격을 쓴다. 새 정원용 경계가 필요한 경우에만 새 규격을 추가한다.
- 교량과 공단: 현재 진행 중인 별도 자산 계열을 수정하지 않는다. 공원 프리뷰에서 필요하면 읽기 전용으로 참조한다.

기존 LOD 거리는 수목 0~100/100~350/350~3000m, 대나무 0~70/70~250/250~2200m로 현재 매니페스트에 기록돼 있다. 신규 자산의 거리는 아래 초기값으로 시작하되 이와 같은 거리로 무조건 통일하지 않는다.

## 4. 1차 제작 묶음

목록의 P0 가운데 12개 계열을 첫 묶음으로 선정한다. 신규 설계·제작 7개와 기존 활용·확장 5개다. LOD·색상·계절·크기 변형을 별도 종류로 중복 계산하지 않는다.

| 순서 | 대상 | 완료 시 얻을 결과 |
|---|---|---|
| 1 | PK01 지표 + PK02 짧은 풀 | 관리 잔디·자연 초지·맨흙이 연결되는 바닥 표현과 가까이 보이는 풀 군락 |
| 2 | PK03 낮은 초화 + PK04 키 큰 초화 + PK05 관상용 풀 | 혼합 화단·꽃길·자연주의 화단을 만드는 3개 기본 실루엣 |
| 3 | PK06 생울타리 + PK07 기존 관목 + PK14 조경석 | 화단·녹지의 경계와 비정형 가장자리 |
| 4 | PK08 활엽수 + PK10 대나무 + PK11 보행로 + PK13 벤치 | 기존 자산을 포함한 5가지 공간 조합 프리뷰 |

식생은 처음부터 많은 품종을 만들지 않는다. 군락마다 실루엣 2~3개, 밀도 2단계, 제한된 색 변형으로 시작한다. 같은 형태의 무작위 회전·크기 변형으로 해결되는 차이는 새 GLB로 만들지 않는다. 종별 특징이 필요한 무궁화·작약·국화 등은 P1에서 실제 사진·도감 대조 후 분리한다.

## 5. 형태·재질·계절 설계

- 외관은 현재 프로젝트의 단색·무광 경량 모델과 맞춘다. 식물은 제한된 자연색을 사용하고 프리뷰 조작 UI는 흑백으로 구성한다.
- 초화는 잎 덩어리, 줄기, 꽃머리의 큰 실루엣을 우선한다. 가까운 전시용 소수 개체와 넓은 군락용 메시를 분리한다.
- 똑같은 사각 패치 경계가 반복되지 않도록 성긴 끝단·빈틈·길 가장자리형을 준비한다. 밀도를 높이는 것으로만 반복 무늬를 가리지 않는다.
- 봄·여름·가을·겨울 상태는 처음에는 재질 색과 꽃 유무·마른 꽃대 선택으로 표현한다. 구조가 실제로 달라져야 할 때만 별도 메시를 만든다.
- 원경 색 덩어리를 만드는 식생과 가까이 관찰할 개체의 규격을 구분한다. 색 변형은 가능하면 인스턴스 데이터로 공유한다.
- 꽃잎을 위한 다수의 겹친 반투명 판은 기본 방식으로 쓰지 않는다. 불투명 기하 우선, 카드가 더 유리한 자산만 알파 컷아웃을 비교한다.
- 바람은 식물별 개별 스크립트 대신 공유 셰이더와 인스턴스 위상값으로 처리한다. 원경에서는 변형 빈도·강도를 줄이거나 생략한다.

## 6. 초기 성능 예산

아래 수치는 제작 목표이며 측정된 성능이나 FPS 보장이 아니다. 삼각형 수는 단일 개체 또는 명시된 군락 메시 한 개 기준이다. 양면 기하와 실제 인스턴스 반복분은 최종 렌더 비용에 포함해 계산한다.

| 자산 단위 | 근경 목표 | 중경 목표 | 원경 표현 | 초기 거리 제안 |
|---|---:|---:|---|---|
| 짧은 풀 0.5~1m 군락 | 24~80 삼각형 | 8~24 | 군락 소거, 지표 재질에 통합 | 근경 0~20m / 중경 20~60m |
| 낮은 초화 1~2m 군락 | 80~240 | 24~80 | 4~16 삼각형 또는 지표 색 영역 | 0~35 / 35~100 / 100~250m |
| 키 큰 초화·관상용 풀 1~2m 군락 | 64~180 | 16~60 | 4~12 삼각형 | 0~40 / 40~120 / 120~350m |
| 관목 1개·생울타리 2m 모듈 | 48~160 | 16~48 | 8~16 삼각형의 단순 체적 | 0~60 / 60~180 / 180~500m |
| 조경석 1개 | 24~80 | 12~32 | 8~12 삼각형 또는 소거 | 0~60 / 60~180 / 최대 400m |
| 안내판·쓰레기통·소형 등 1개 | 60~220 | 12~60 | 작은 것은 소거 | 0~40 / 40~120m |

거리값은 카메라 높이·화각·모델 크기·스케일에 따라 조정한다. 화면에서 한두 픽셀에 불과한 작은 자산을 먼 거리까지 유지하지 않는다. 나무·대숲은 기존 LOD와 매니페스트를 활용하며 현재 자산을 표의 신규 군락 예산에 맞추려고 덮어쓰지 않는다.

기본 원칙은 반복 식생 메시당 1개 표면·공유 재질이다. 필요할 때만 근경 시설물에 2개 이하 표면을 허용한다. 그림자는 근경 수목·큰 시설 위주로 두고 작은 풀·꽃·원경에는 기본적으로 끈다. 식생에는 기본 충돌을 넣지 않으며 벤치·난간·데크의 충돌은 별도 선택 자산으로 둔다.

## 7. 배치와 조합 규격

- 단위는 m, Y축 위쪽. 개체·군락은 바닥 중심 Y=0, 띠 모듈은 접속 단면 중심을 기준으로 한다.
- 생울타리·화단 경계는 1/2/4m 직선과 선택 곡선·끝단으로 구성한다. 이 치수는 범용 모듈 설계값이며 실제 국가정원 시설 치수가 아니다.
- 보행로 접속점은 기존 road_assets의 Marker3D -Z 바깥 방향과 단면 profile을 유지한다. 임의 확대 시 접속 폭·높이의 변화를 기록한다.
- 군락마다 footprint와 배치 여백, 허용 경사, 바닥 삽입량을 메타데이터로 둔다. 바닥 삽입으로 공중부양을 감추는 대신 국소 지형 표본에 맞춘다.
- 동일 모델·재질의 식생은 MultiMesh로 묶되 공간 청크를 나눈다. 작은 식생은 32m, 나무·대숲은 기존 64m 청크를 초기 후보로 비교한다. 공원 전체를 하나의 MultiMesh로 묶지 않는다.
- 길·계단·배수로·수면·시설 접근 공간을 배제 마스크로 분리한다. 실제 홍수 범람구역이나 공원 허가 경계를 배제 마스크만으로 확정하지 않는다.
- 배치 결과에는 고정 시드, 자산 키, 변환, 구역 ID, 사용 마스크 해시를 기록해 재현 가능하게 한다. 인스턴스마다 독립 스크립트·광원을 붙이지 않는다.
- 안내판은 메시와 문구 데이터를 분리한다. 실제 안내 문구·지도는 확인한 자료를 사용하며 범용 프리뷰에는 임시 문구임을 표시한다.

## 8. 독립 조합 프리뷰와 확인 범위

| 조합 | 핵심 자산 | 확인할 점 |
|---|---|---|
| 잔디광장 | 지표·짧은 풀·수목·벤치 | 지표 연결, 풀 밀도, 같은 패치 반복감 |
| 꽃길 | 낮은 초화·키 큰 초화·길·경계 | 통로 침범, 곡선 접속, 꽃색 덩어리 |
| 자연주의 화단 | 관상용 풀·다년초·마른 꽃대·조경석 | 높이 혼합, 비개화 상태, 군락 간 빈틈 |
| 대숲 가장자리 | 기존 대나무·관목·낮은 풀·맨흙 길 | 잎의 통로 침범, 숲의 경계, LOD 차이 |
| 그늘 휴게 공간 | 기존 활엽수·벤치·피크닉·보행로 | 스케일, 바닥 높이, 이동 여백 |

가벼운 100 × 100m 합성 구역 하나를 대표 대량 배치 확인용으로 제안한다. 예시 상한은 수목·대나무 개체/군락 200개, 작은 식생 군락 2,000개, 시설 30개, 보행·경계 모듈 150개다. 실제 국가정원의 밀도를 뜻하지 않는다. 가까운 카메라와 높은 카메라 각각에서 표시 인스턴스·렌더 삼각형·드로콜·프레임 시간·식생 겹침을 기록하고, 밀도와 청크 크기를 조정한다.

작업마다 전체 맵은 실행하지 않는다. 검증은 생성물 구조, 원본 해시 보존, 대표 조합·LOD 전환·곡선 접속에 한정한다. 이후 실제 맵 통합을 별도 수행할 때만 넓은 구역 성능을 측정한다.

## 9. 저장 구조와 산출물

아래는 향후 제작 시 사용할 제안 경로다. 이번 문서 작업에서는 생성하지 않는다.

```text
pipeline/processors/park_vegetation/   식생 기하·제원·LOD·카탈로그 생성
pipeline/processors/park_fixtures/     새 공원 시설·경계 생성
config/park_asset_profiles.json       크기·밀도·LOD·계절 제안 규격
godot_project/assets/generated/park_vegetation/  새 식생만 저장
godot_project/assets/generated/park_fixtures/    새 시설만 저장
previews/asset_browser/park_assets_check/        합성 구역·임포트·로그
results/                             제작 보고·원본/파생 비교
```

- 기존 trees/bamboo/garden_furniture/road_assets는 읽기 전용으로 활용한다. 보강 자산도 새 전용 경로에 저장하고 원본을 덮어쓰지 않는다.
- 기능은 제원·기하·출력·카탈로그·배치 조합·프리뷰로 나누고 새 모듈은 __init__.py 또는 module_index.json에 노출한다. 600라인에 도달하기 전에 분리하고 800라인을 초과하지 않는다.
- 기본 산출물: GLB 또는 경량 PackedScene, 대응 씬, 필요한 LOD, 카탈로그·전용 매니페스트·README, 비교 PNG, 간단한 생성 보고서.
- 메타데이터: 원본·출처, 자산 키, 단위·원점, 로컬 AABB, footprint·여백, 계절·변형 키, LOD 거리·삼각형·표면 수, 충돌·그림자·바람 상태, 포트, 해시. 실제 지리 정보가 없으면 bbox·해상도는 null로 기록한다.
- 실제 제작 시 새 계열의 분류 코드와 ASSET_INDEX_GUIDE.md를 함께 갱신하고, 공통 generated/manifest.json에는 기존 항목을 보존하며 병합한다.
- 제작 완료 후 지정된 수동 색인 명령을 실행한다. 가상환경이 이전 사용자 경로를 참조하면 공유 환경을 바꾸지 않고 명시적 설치 Python 경로로 같은 스크립트를 실행해 결과를 기록한다.
- 프리뷰는 안정된 파일만 전용 공간에 복사해 임포트한다. 게임 원본 .godot/.import·씬·설정에는 쓰지 않으며 에셋 변경만으로 프리뷰 EXE를 재빌드하지 않는다.
